# 外部提案の暫定ロードマップ

2026-09-03 記録。オーナーが共有した、外部AIからの独立提案を比較するための暫定ロードマップ。

**これは要件でも、採用決定でも、実装順でもない。** 各提案は、その時点の MediNode の設計とコードを
確認したうえで個別に評価する。ここに並ぶ論点は「いずれ比較する予定の題目」であって、
着手の合図ではない。

## 提案済み

### 提案001：読む→残す→確かめる

リーダーで触れた主張を Node として残し、Recall で再確認するまでの接続。

決定と実装計画は、提案001の文書に従う（本ロードマップはその内容を上書きしない）。

### 提案002：Recall の本質と一般公開

作り込まれている既存 Recall を基準に、以下を比較する。

- 再確認
- 新しい知識との出会い
- 初回体験
- 用語
- 一覧表示
- アクセシビリティ
- 公開範囲
- 契約終了後の扱い

**既存 Recall の置き換えを前提としない。**

## 今後共有予定

以下は共有予定の題目と論点のみ。採用も着手もされていない。

### 提案003：ホーム画面とナビゲーション

現在の7タブや各機能の入口を、ユーザーの行動から再評価する。

- 検索、新着、ジャンル、文献、クイズ、マニュアル、Recall の関係
- 起動直後に何を見せるか
- 検索をどこからでも使えるようにするか
- CQ の入口
- 「探す・残す・確かめる」などの行動単位による整理
- 既存の7タブを維持する案との比較

### 提案004：記憶と根拠の二重鮮度

個人の復習状態と、医学的根拠の更新状態を混同せず扱う方法。

- 復習時期
- 文献・ガイドラインの更新
- 主張の改訂
- 旧版と新版
- Recall 上の表現
- 「記憶を測定している」と誤解させない表示

### 提案005：検索ゼロ件から CQ・記事化への循環

検索結果がない状態を、単なる失敗画面で終わらせず、次の知識を作る入口にする方法。

- 自分の Notion へ残す
- 作者へ疑問を送る
- 類似 CQ
- 投票
- 回答通知
- 記事化
- 新しい Node として戻るまでの循環
- 作者一人で運用できる上限

### 提案006：Node の情報構造

Node を単なる主張本文ではなく、医学知識の最小単位としてどこまで構造化するか。

- 主張 / 出典 / 確信度
- 適用対象 / 適用条件 / 例外
- 記事・節・診療分野
- 更新履歴
- 個人メモ
- 部署の運用との区別

**既存の Claim ID 変更は前提にしない。**

### 提案007：AI を使う範囲・使わない範囲

現在の「アプリ内で AI に医学的回答を生成させない」という思想を基準に、
AI を安全に利用できる境界を検討する。

- 主張候補の抽出
- 検索語の補助
- 構造化
- 関連 Node 候補
- 人間による承認
- 逐語検査
- AI が関与した部分の表示
- AI へ任せない判断

### 提案008：ビジュアルデザインとモーション

MediNode 全体の見た目と操作感を、一つの視覚言語へ統一する方法。

- 配色 / タイポグラフィ / 余白
- Node の形
- 記事と Recall の接続表現
- アニメーション / 触覚反応
- ダーク／ライトテーマ
- 読みやすさ
- 医療器具としての静けさ
- Recall だけを特別な空間として扱うか

### 提案009：無料・有料の境界

「無料＝道具、有料＝中身」という現在の原則を含め、課金体験を再評価する。

- 自分の Notion 検索
- 作者の検証済み記事
- Recall
- CQ 投稿
- 無料体験
- note 購入特典
- 解約後のデータ
- 有料コンテンツの保護
- 月額課金を継続する理由

### 提案010：Notion との関係

MediNode にとって Notion が原本なのか、入口なのか、任意の連携先なのかを整理する。

- Notion 利用者と非利用者
- 初期設定 / OAuth
- 自分の知識と作者の知識
- Notion 接続を求めるタイミング
- Notion 依存の利点と限界
- 利用者自身のメモを Node 化する可能性

## 運用上の注意

1. 各提案は**未採用の独立案**として共有する
2. 以前の提案を、オーナーの明示的決定なしに確定事項として扱わない
3. 後続提案の論点を、現在の実装計画へ先回りして混ぜない
4. 現在の提案で見つかった別領域の問題は、該当する後続提案へ送る
5. セキュリティ・権限・データ破損などの重大事項は、**後続提案を待たずに報告する**
6. 提案の順番は、現行実装やオーナーの判断によって変更できる
7. 最終的な採用判断と実装は、オーナーと Claude Code が行う
