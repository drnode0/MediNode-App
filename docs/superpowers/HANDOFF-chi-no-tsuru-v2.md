## ⚠️ 未解決の設計問題（オーナー裁定が要る）

### 1. 生き物の実物が、虫が苦手な人には不快になりうる【最重要・2026-08-04オーナー指摘】

ラダーの序盤8つのうち **4つが生き物**（アリ5mm・テントウムシ8mm・カタツムリ3.5cm・スズメ10cm）。第7波で「絵の高さ＝地面から朱線までの距離」にした結果、**越えた瞬間と次の目標のゴーストが、実寸比で大きく描かれる**（カタツムリ3.5cm＝245px）。虫が苦手な人にとっては、ただ気持ち悪い画面になる。

**真因は大きさではなく、絵の性格だと見ている。** いま `public/vine/` にある生き物のPNGは**博物図譜寄りの写実画**で、アリは脚と触角が精密に描かれている。鳥獣戯画は戯画（デフォルメ）であって博物画ではない。世界観の看板と実物の絵が食い違っている。

**オーナー裁定（2026-08-05）＝ A＋Bの部分適用。** アリとテントウムシ（最小の2つ＝いちばん拡大される）を非生物へ差し替え、カタツムリ以上は戯画寄りに描き直す。C（生き物だけ小さく描く＝物差しが2本に逆戻り）とD（設定で隠す＝負債）は不採用。

**→ いまは素材待ち。** 発注書は `specs/2026-08-01-chi-no-tsuru-asset-orders.md` の末尾「追加発注（2026-08-05・虫の件）」に**5点ぶんの生成プロンプトつきで**書いてある（新規＝小豆・大豆／描き直し＝カタツムリ・雀・猫）。**【戯画LOCK】**を STYLE LOCK の直後に貼るのが要点——旧発注文は「線は少なく」としか言っておらず、戯画を一度も指定していなかった。

差し替えの実寸は裏取り済み（小豆5.5mm＝大納言の下限〔商慣行規格・弱い方の裏取り〕／大豆7.9mm＝農産物規格規程の大粒）。**葉数は動かない**（3枚・4枚のまま）。⚠️ ただし到達済みの目次で「アリを越えた」が「小豆を越えた」に**遡って書き換わる**——記録は1件も動かないが、越えた相手の名前は変わる。

素材が揃ったあとのコード側4手順も同じ発注書の末尾にある（`vine-ladder.ts` の実寸2件・`INTRO_LINES` の「アリを越え」→「小豆を越え」・`MILESTONE_ART` の再実測・ゴールデンテスト）。**素材が来るまで着手しない**——絵の無いラダーを先に入れると、いま出ている背くらべが2つ消える。

### 2. 正典§10「4状態は塗りの密度で分ける」の改訂が未承認

実測で葉身は16.6〜31.9px。**この寸法では明度差は読めない。** 第7波では形・縁・大きさ（照り葉は1.18倍＋金泥の縁、褪せは輪郭を足す）を併用したが、§10は「一次文献で検証済みの描画規則を変更しない」と明記しているので、**勝手に動かせない**。「塗りの密度」→「塗りの密度＋形」への改訂の可否を裁定すること。

### ~~3. 葉タップから知識の本文へ飛べない~~ → **実装済み（2026-08-05・`2c1d019`）**

葉のシートに本文への導線を1つ足した。**行き先は台帳のidだけで決まる**（`src/lib/vine-open.ts`）——検索レコードの `objectID` が `${owner}_${pageId}` で統一されているので、`Step` に owner や URL を足していない。足すと「古い葉だけ本文へ行けない」という壊れ方をする。

| idの接頭辞 | 行き先 |
|---|---|
| `subscription_` | アプリ内リーダー（**蔓は閉じない**＝本文を閉じたらこの画面に戻る）。プレミアム失効中は出さない |
| `personal_` / `team_` | Notionを開く（アプリ内リーダーは `/api/subscription/page` が会員ゲートで配信専用のため） |
| それ以外・id形式が読めない | 何も出さない（押せない導線は無いより悪い） |

devハーネスに「本文への導線（配信・個人・見本）」シナリオを追加。⚠️ **ハーネスには `ReaderProvider` が無いので「本文を読む」は押しても何も起きない**（`useReader` が no-op を返す契約）——ここで見えるのは「どの葉にどの導線が出るか」だけ。**リーダーが実際に開くかはオーナーの実機（プレミアム＋tower）でしか確認できない。**

## 壊してはいけない不変条件

- **`VineScene` の `<svg>` は `viewBox` と `width`/`height` を同値にする。** 崩すと `scrollTop`（CSS px）と `leafY`（viewBox単位）がズレ、深くスクロールするほど葉が消える。`w-full` や `max-w-*` を足さない
- **`PX_PER_LEAF` は縮めない。** 葉数に応じて間隔を詰めるのは v1.2 が破綻した原因そのもの（葉95枚で間隔2.4px＝去年の学びが名前のない緑の楕円になる）。カメラ（`sceneOffset`）は「短いときに構図を与える」だけで、長いときの挙動を変えない
- **`GROUND_GAP === PX_PER_LEAF`。** 崩すと丈が `GROUND_GAP+(n-1)*14` と非線形になり、小さい実物ほど大きく描かれる（40pxだった頃はアリが+94%）
- **`COMPOUND_START_LEAVES × COMPOUND_RATE === 1`。** 崩すと複利開始と同時に減速する。テストで固定済み
- **VineScreen と VineScene は同じ `offset` を使う。** ズレると目次の飛び先が全部狂う
- **紙の色は `--washi` 一箇所で決める。** 直書きすると時刻トーンとズレて、夜に帯やシートだけが光る
- **色褪せ・未読・連続日数を数えてUIに出さない**（負債台帳化の禁）
- **画面文言は `src/lib/vine-copy.ts` を通す。** 直書きすると六つの禁の走査に載らない
- **数字・進捗・催促を足さない。** 「あと◯枚でネコ」「今週の目標」「連続◯日」「達成率」は7波かけて守ってきた思想（正典§14の禁5・§7「負債台帳にしない」）を1回で壊す。**体験が悪いと言われたときに最も出やすい改善案がこれで、入れると悪化する**

## 判断の記録（蒸し返さないために）

### 設計の背骨

- **蔓の開放判定は段Aの `tower` フラグに一本化。** 実装中に別セッションが「機能別の先行体験」を main へ入れており、同じ問題をより良く解いていたので自前の `vine-access.ts` は破棄した。**並行システムを作らないこと**
- **持ち込んだ知識は地下茎にする。** 地下に本葉は生えない＝地下にあるのは「まだ芽を出していない知識」。読み返す・思い出すと地上に生まれ直す。バックフィルは一瞬でも地上に出すには時間がかかるので、序盤が食い尽くされない
- **雲の先＝測るのをやめる＋季節の点景と出会う。** 「比べる相手が自分の去年になる」案は却下（姿がなく、比率になり、数字で集計しない思想と衝突する）
- **点景は通知しない。** 開いたときに見つけるもの
- **地上0のとき数字を出さない**（「0mm」「ぜんぶで0枚」は最初の一画面を0で語る）。ただし**情報を全部消してはいけない**——初見レビューで「いちばん寂しい日にいちばん情報が少ない」と指摘され、常設の導線を足した

### 撤回した判断

- ~~`joinedAt` の重複規則は緩めない~~ → **撤回（実機で「全く動いていない」）**。地下の歩まで見て弾くと生まれ直しが死ぬ。「一生に1回」は地上スコープで守る形に修正（`recallKindFor` 新設）。水増し防止は、地下候補の全歩照合と地上内の1回規則で引き続き成立
- ~~「見本の蔓を一瞬グイーンと伸ばす」~~ → 初めて開く人には一瞬にしか映らない。タップで進む4段のオンボーディングへ
- ~~見本500枚~~ → 60枚。**他人の巨木を見せてから0枚を渡すのは約束違反**（3視点とも一致）
- ~~実物の絵は葉数×14×0.85・上限64px~~ → 物差しは1本（地面から朱線までの距離）

### 文言の確定（[[tatsuki-buntai-profile]] と一体）

- **ポーズを取る文は落ちる。** 詩的な口上（「一本の蔓を」「きょうひらく」「種はもう手のなかにある」）は全部却下された——1行も新しい事実を運んでいなかったから
- **ただし数字の列挙も違った。** 寸法は画面の朱線が持っているので文言では繰り返さない
- **確定した4行**＝「日々の学びが 少しずつ蔓になる／読む・書く・思い出す——そのたびに 葉がひらく／アリを越え 湯のみを越え 鳥居を越え／じぶんの蔓は どこまでのびるだろう」。**弧を描いて、最後を開いた問いで渡す**（答えは直下の行動ボタンで本人が出す）
- **世界観を言葉で名乗らない**（「これは豆の木の話」は子供っぽい）。世界観は絵と構造で示す
- 敬体と二人称は使わない（六つの禁）。オーナー原案の「〜成長します。あなたの蔓は〜でしょうか」は常体・「じぶん」へ変換して採用

### 第7波の詳細（2026-08-04・8つの不満は本当は4つの根本だった）

**根本1: カメラが無かった**——唯一の画面制御が `maxHeight:'70vh'` だけで、地面の位置が葉数で動いていた。葉3枚＝蔓28px・空白が箱の54%。→ `sceneOffset(aboveTotal, depth, viewportH)` を新設し、シーンが画面より低いときは上に余白を足して**地面を画面の下寄りに固定**。leafY/groundY/sceneHeightPx/visibleRange/markPositions/laneMarks/sceneryMarks は末尾に `offset` を取る（既定0なので既存テストは不変）。

**根本2: 物差しが2本あった**——縦軸は葉の番号、絵の大きさは別式。実寸80倍差のアリと一升瓶が画面では1.8倍差で、全部が地面から浮いていた。→ 絵の高さ＝**地面からその朱線までの距離**に統一。`GROUND_GAP` 40→14（PX_PER_LEAF と同値）。**PNGごとの余白率（インクが画像高の31%〜77%）を topFrac/hFrac で補正**——これが無いと5mmのテントウムシが5mmのアリより小さく描かれる。

**根本3: 墨絵に光源と濁色を持ち込んでいた**——`.obi` の白い暈、紙より明るい帯（夜1.85:1）、夜トーン `#CBB58C` は薄墨が1.90:1で**文字が物理的に読めない**、ダークモードは時刻を無視して常時最濃。→ 光る帯を全廃（口上は絵の外へ）・`--washi` に集約・色をコントラストで決め直し（朱 `#A8342A`／薄墨の文字 `#5F5849`・図形 `#7C7462`／苔 `#55643C`／銀鼠 `#9AA096`／夜 `#E3D6B6`）。

**根本4: 主役の解像度不足**——葉は実効8.7〜24pxで4状態の差が全部「塗りの明度」だった。地下茎は**画像の上45%が地面より上に描かれ、本物の幹の隣に淡いゴースト新芽が重なっていた**（＝「根の形が気に入らない」の正体）。マスクも上下逆でひげ根を消して走茎の棒だけ残していた。→ 葉に20pxの床＋照りは1.18倍＋金泥の縁。地下茎は窓で地上を切り落としマスクを反転。

**致命傷2つ（初見レビューが発見）**
- **葉0枚のユーザーは「今日の1問」へ行く導線が画面に存在しなかった**（出口ボタンは口上の最終段だけ）→ フッターに常設
- **葉4枚に達した瞬間、アリのラベルと絵が永久に消えていた**（右レーンが新しい側優先）→ 最初の1つは無条件でラベルを残す

## 無関係な既存バグ（触っていない）
