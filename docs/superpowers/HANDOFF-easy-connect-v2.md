| 段 | 内容 | 状態 |
|---|---|---|

**使えるのは `easy_connect` 機能を持つアカウントだけ。** それ以外の人には入口も出ず、サーバー側も理由を出さずに拒否する。付与は /admin のアカウント台帳 →「先行体験」→「かんたん接続（OAuth検証）」。

## 通る道筋

```
/api/notion/oauth/start
  → 中間ページ /connect/notion（「Notionを開いて許可する」／PCへのリンクコピー）
  → Notionの認可画面（ページを選んで許可）
  → /api/notion/oauth/callback（セッションを読まない。トークンは oauth_states に暗号化して置くだけ）
  → 完了ページ /connect/notion/done（保存先アカウントをマスク表示）
  → アプリを開く
  → GET /api/notion/oauth/claimable → あれば POST /api/notion/oauth/claim
  → 仕上げシート：DB選択 → 列確認 → 保存
```

**callback がセッションを読まないことが、この設計の中心。** iPhoneのスタンドアロンPWAはSafariと別ストレージなので、認可を終えたブラウザにMediNodeのセッションが無い。v1はそこでユーザーを特定していたため、最も普通の経路で完走できなかった。

## 実機で確認できたこと（2026-08-03・オーナーのアカウント）

- PCで認可 → 完了ページに自分のメールがマスク表示される
- アプリを開くと仕上げシートが自動で開き、**Medical DB と Reference DB が最初から選択された状態**で出る
- **権限が足りないときの保護が正確に働く**：Medical DBのあるページだけ許可して参考文献・マニュアルのページを許可せずに進めたところ、その2つだけを名指しして「今回の接続では見えません」と出て、**設定は書き換わらなかった**

## 運用の地雷

**メインの作業コピーは他セッションがブランチを切り替える。** `~/medical-search-public` は `main` に居るとは限らない。実際に一度、別ブランチにマージしてしまい `git reset --keep` で戻した。**`git checkout` で奪わない。** `main` へのマージは一時worktree（`git worktree add <path> origin/main --detach`）で行い、共有コピーが `main` かつクリーンなときだけ直接触る。

**migration は手で流す。** 0021（`early_access_features`）・0022（`oauth_states`）・0023（索引）は適用済み。台帳は `supabase/migrations/README.md`。

**Notion側のリダイレクトURI**は本番ドメインのみ登録されている。localhostで試すなら、そのURLも登録しないと認可が通らない。

**`admin-engagement-route.test.ts` が時刻依存で揺れる。** このブランチと無関係。別タスクに切り出し済み。

## この仕事で潰した重い不具合（再発防止のため残す）

いずれもレビューで見つかったもの。設計どおりに書いたつもりでも入っていた。

| どこ | 何が起きるはずだったか |
|---|---|
| `redirect_uri` を2箇所で別ロジックで組み立て | LAN実機（`http://192.168.x.x:3000`）での検証中にNotionが交換を拒み、原因は静かなエラーに埋もれる |
| conflict で残した state 行 | 後で自動claimされ、**一度拒否した狭いトークンで動いている接続を上書き**する |
| claim経路のDB選択が復元されない | 「Notionでページを選び直す」から戻ると **Reference DB が黙って消える** |
| IDの正規化違い（保存側はハイフン無し32桁／Notionはハイフン付き） | 上の復元が**手動セットアップ組の全員で外れる** |
| `hadServerSettings=true` で応答を丸ごと書く | サーバーのスナップショットが古いと、**未同期の端末設定が端末とサーバーの両方から消える** |
| 一時障害を「見えません」と断定 | 通信が切れただけで**不要な再認可へ誘導**する（claim側・保存前の両方にあった） |
| conflict を断っても破棄されない | **1時間のあいだ毎回起動時に全画面で再提示**され、アプリに入れない |
| `mountedRef` を true に戻していない | Strict Mode（dev）でボタンが**永久に無効化**される＝手動確認の場所そのもの |

共通しているのは「壊れても静かで、原因が分からない」こと。**この機能は失敗が沈黙しやすい。** 変更するときは「失敗したとき何が見えるか」を先に決めること。
