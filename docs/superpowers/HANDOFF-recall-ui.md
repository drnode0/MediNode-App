# Recall の UI こだわり集（引き継ぎ・2026-09-11）

`HANDOFF-recall.md`（全体像）の姉妹編。**Recall の画面を触る人が、直す前に知っておくべき「なぜそうなっているか」だけ**を集めた。
数値・規則の正は各設計書とコードのコメント。ここは索引と理由。

## 0. 貫いている5つの掟

| # | 掟 | 破ってよい唯一の例外 |
|---|---|---|
| 1 | **線画。面・塗り・影を使わない。** 線と点だけで描く（LP・紋章と揃える） | 宇宙の空席の「ガス」（淡い光の霧。R8 で明示的に例外と決めた） |
| 2 | **暖色（金）は離れかけにだけ。** 他の状態は線の色の濃淡だけで分ける | なし |
| 3 | **判断は純関数（`src/lib/recall/`）に置き、部品はモデルを写すだけ。** 点の見た目・並び・配置・文言はすべて `dex.ts` `field-*.ts` `srs.ts` `notice.ts` が決める | なし。部品側に式を書いたらテストできない場所に判断が移る |
| 4 | **見た目はコードで回る現物で決める。** 静止画で案を選ばない。実機・playwright で測ってから決める | なし |
| 5 | **言葉の規律。** 「定着」と書かない（＝深く残した）。振る・拾う・血肉・落ちる・惑星・輪・席は画面に出さない | なし |

## 1. 情報設計：1軸に全部を載せた

Recall が持っている情報は5つの状態（未着手・読んだ・残した・深く残した・離れかけ）だが、
**軸を増やさず「中心に近いほど／濃いほど自分のもの」の1軸**に全部載せている。

- 惑星の時代は「輪からの距離」で表し、境目に名前を3秒出して説明していた
- 標本帳にしてからは **点の濃さ**で表し、**説明が要らなくなった**（凡例は出すが、無くても読める）
- 「読んだ」と「残した」の見分けが弱い、という初期の未解決は、色ではなく**居場所・濃さの差**で解いた

**並びは動かさない。** 一覧は席番号順で固定（離れかけ順に並べ替えない）。点の並びは
「記事の初出順 → 節の順 → 作成順」で、主張が増えても既存の相対順が変わらない。
図鑑は**並びが動かないことで場所を覚えられる**、が理由。並べ替え・絞り込みの機能はあえて付けていない。

## 2. 一覧（標本帳）

| こだわり | 中身 |
|---|---|
| 標本ラベルの枠 | 1px の線＋**左上・右下だけの角の印**（`before`/`after` の疑似要素）。角丸・影は使わない |
| 紋章は名前の先頭に揃える | `items-start`。PC幅2列で名前が折り返しても、紋章が名前とトレイの中央に浮かない（ブラッシュアップ候補3） |
| 名前は3行固定 | 和名17px／英名11px・字間 .12em・大文字／族名11px。`flex-wrap` で横に流すと、名前の長さ次第で枚ごとに組み方が変わる |
| トレイの幅は**実測** | 固定値（560/270px）で始めたら、2列時の実幅は約176pxしかなく `trayLayout` が「6行に収まる」と誤判定して点が枠からはみ出た。`ResizeObserver` で自分の幅を測る |
| 測れるまで描かない | 初期値を `null` にして、幅が来るまでトレイ自体を出さない。固定値の仮並びを1コマだけ見せない |
| 点は 6px→4px→「ほか n」 | 6行を超えたら点を小さく、それでも超えたら入る分だけ見せて残数を出す（`trayLayout`・`TRAY_MAX_ROWS 6`） |
| 「ほか n」は点の容器の外 | 同じ `flex-wrap` に混ぜると7行目に折り返して「6行に収める」約束が崩れる（実測で発生） |
| 数字は `tabular-nums` | 件数が並ぶ画面なので桁が揺れない |
| 説明は1文＋折りたたみ | 常時1文、細かい話は `<details>`。**初めての人は開いた状態**、閉じたら記憶する（`localStorage: recall.aboutOpen`。壊れた値は「開く」に倒す＝説明は隠すより見せる） |

## 3. 分野ページ：縦の列挙をやめた

**きっかけは実測。** 呼吸（178件）を主張1行ずつ縦に積むと、スマホ幅で **13,523px**（1行約75px×178）。
点の地図に書き直して **2,172px**（16%）になった。

| こだわり | 中身 |
|---|---|
| 点 14px・間隔 6px・**当たり判定 26px** | 点は `aria-hidden` の `<i>`、押す役目は親の `<button>`。当たり判定は `::after` の `-inset-1.5` で広げる（見た目を太らせずに指で押せる） |
| **1回押す＝本文1行、2回押す＝カード** | いきなりカードを開かない。開いている1行は分野ページで常に1つだけ。離れかけの行には「もう一度押すと確かめる」と書く |
| 貼り付き位置は**実測** | アプリのヘッダー（`[data-app-header]`）は高さが端末と safe-area で変わる。定数 120px と書いたら実測98pxとの差で **22px の隙間**が空き、中身がそこを通り抜けた。`ResizeObserver` でヘッダーと目次の高さを測って `top` に入れる |
| 目次チップの追従 | `IntersectionObserver`（`rootMargin` にヘッダー＋目次の実測を入れる）で、いま画面にある記事のチップだけ濃くする |
| 記事見出しと節見出しを一目で分ける | 記事＝本文の色・15px・**左に3px の縦線**・`color-mix(ink 6%)` の帯。節＝11px・薄い色。試作初版（灰12.5px）は区別が付かずボツ |
| `scrollMarginTop` | 目次から飛んだ見出しが貼り付き帯の下に潜らない |
| 記事1つでも目次を出す | 統一。分野によって構造が変わらない |

## 4. カード

| こだわり | 中身 |
|---|---|
| **背面に覆いを敷く** | 覆いが無いと、カードの上に覗いている点を押せてしまい、閉じたつもりが中身だけ別の主張に差し替わる（2026-09-05 実画面で確認）。覆いは隠しコマンド(z-20)より上・カード(z-30)より下の z-29 |
| 答えてから **0.9秒** 見せる | 「覚えた／まだ」で答えると穴の答えが出て、0.9秒後に閉じる。押した瞬間に消さない |
| 伏せ字は `min-w-[74px]` の下線 | 空欄の幅で答えの字数を悟らせない。開くと同じ位置に水色で答えが入る |
| **表示のときに穴を作らない** | 伏せ字にするのは承認済み＋整えた後にも範囲が残るときだけ。無ければ想起カード（全文伏せ）に落とす。管理画面と読者側は同じ `segmentBody` を通す（「管理画面での見え方」と「読者の見え方」を絶対にずらさない） |
| 「閉じる」を必ず置く | 答える前・答えを見ている間・保存が詰まっている間、どの状態でも抜けられる。閉じても記録は書かない（誤タップ対策と、保存の取り消しは別物） |
| 保存中の表示 | 回線が細いと数秒かかるので `記録しています`（`role="status"`）を出し、操作不能に見せない |
| 選択肢・AI解説を出さない | 設計の約束。思い出す以外のことをさせない |

## 5. 紋章（canvas を15枚並べる工夫）

- **共有 rAF**（`emblem-loop.ts`）。部品ごとに rAF を持たせるとタブが重くなるので1本にまとめ、**30fps に間引く**
- `IntersectionObserver` で**画面外の紋章は描かない**
- `visibilitychange` でタブが隠れたら止め、戻った1コマは必ず描く
- **テーマ替わりだけは別枠**（`MutationObserver` で `<html>.dark` を見て全紋章を1回描き直す）。
  画面外で間引かれた紋章に古いテーマの線色が残るため
- canvas は**塗りつぶさない**（`clearRect` のみ＝透明）。plate の背景を透かすことで線画の原則に合い、
  再描画前に見えても「白い箱」にならない
- `devicePixelRatio` は 2 で頭打ち。テーマは毎フレーム DOM から読む（フックの初回値 false を使うと、ダークで開いた最初の1コマだけ地が白く光る）
- 席ごとの**個体差**（`coreIndividual`：大きさ・速さ・傾き）で、同じ族でも同じ動きに見えないようにしている

## 6. 色とテーマ

- **2組のパレット**（`field-palette.ts`）。canvas は Tailwind の `dark:` で切り替わらないので自前で持つ。
  ダーク＝紺の地に白の線、ライト＝紙の地に紺の線。**同じ世界を裏返しただけで、5段の見分けは変えない**
- **金は1色**。`GOLD_DARK #F0D68A` / `GOLD_LIGHT #A86B0C` を DOM（Tailwind の `text-[#…]`）と canvas（`INK_HALO` の引き直し）で共有し、**テストで固定**。
  Tailwind の class はソース走査で作られるので変数から差し込めない → 変えるときは2か所を一緒に変える、と明記してある
- **ライトは `alphaGain 1.6`**。紙の上では線が沈むので点・輪郭・モヤの alpha を底上げし、`gainAlpha` で 1 に頭打ち
- **光は紙では薄く**（`glow` ダーク0.25／ライト0.12）。紙の上の光は滲みに見える
- ライトの地は `#F5F7FA`（アプリの soft）。ヘッダーの白より一段だけ沈めて「別のアプリに飛んだ」と感じさせない
- ダークで Recall 側は**自前の背景を塗らない**（`dark:bg-transparent`）。ページの地をそのまま透かす。塗るのは隠しコマンドの覆いだけ
- **ブランド色の緑は試して取り下げた**（D6）。実画面で紺のページの中に緑が1本の帯として浮いた

## 7. 動き

| こだわり | 中身 |
|---|---|
| **リングはゆっくり自転する** | 一度「止める」と決めたが、実機で見ると**静止画に見えた**ので改訂（決定14）。`IDLE_SPIN = 0.035 rad/s`（約3分で一周）。指で触っている間と慣性が残っている間は自転しない（手の動きと足し算にならない） |
| 慣性 | 指を離しても回り続けて減速。押さえて止めてから離したときは付けない |
| 覆いは紋章から生える | `transform-origin` を押した紋章の中心に置き、`scale(.2)→1`＋`opacity 0→1` を **500ms**（戻り 350ms・`cubic-bezier(.16,.9,.3,1)`）。元の紋章は出ている間 `opacity-30` に落として「浮き出た」と読ませる |
| 扇形は触れたときだけ | 球では記事の扇形の弧を常時出さない。触れてから 2.6 秒、最後の 600ms で薄れる |
| 族名の説明は押したときだけ | 星団の族名を押すと 3.2 秒（最後 600ms で薄れる）。常時は出さない＝**画面に文字を増やさない** |
| カードは下から立ち上がる | `recall-card-rise .62s`、覆いは `.3s` でフェード |
| 点の変化は 600ms | 答えた点がその場で濃くなる（`transition-opacity duration-[600ms]`） |
| **動きを減らす設定** | CSS は `globals.css` の全体規則で止まるが、canvas と JS の慣性は止まらない。`useReducedMotion` を配って、芯の動き・明滅・弧・自転・慣性・覆いの遷移を**自分で**止める（`motion-reduce:transition-none` も併用） |

## 8. 書体

- 英字 **Jost 300**・字間広め、日本語 **Noto Sans JP 300**。canvas も同じ（`FONT_LATIN` / `FONT_JP`）
- `next/font` は書体名を生成するので、canvas からは CSS 変数 `--font-jost` を1回読んで覚える
- **`ctx.letterSpacing` の対応を判定**して、非対応端末（古い iOS Safari）では**1字ずつ置く**フォールバック（`spacedText`）
- 事故の記録: 以前は `Zen Kaku Gothic New` / `Shippori Mincho` を指定していたが**どこにも読み込まれておらず**、端末の代替書体で出ていた。指定ごと外した

## 9. 操作しやすさ・アクセシビリティ

- すべての操作は `focus-visible:ring-2 ring-cyan-500`（ダークは offset を地の色に合わせる）
- 点の `<button>` は `aria-label` に**主張の本文**を入れ、`aria-pressed` で選択を伝える
- カードは `role="dialog" aria-label="主張のカード"`。**Esc の譲り合い**をしていて、カードが開いている間の Esc は
  カード側が受ける（同時に閉じると、カードを閉じたつもりで球体からも弾き出される）。宇宙から入った球の Esc は覆いを閉じずに宇宙へ戻る
- 行の高さはスマホで 44px 以上、点の当たり判定は 26px
- 目次の横スクロールはスクロールバーを隠す（`[scrollbar-width:none]`）

## 10. 実機で覆した失敗（同じ轍を踏まないために）

| 失敗 | どう直したか |
|---|---|
| 遠景で輪が上下2本の横線に潰れ、真ん中が空洞に見えた | 玄関を惑星から標本帳へ（D1） |
| 主張を縦に列挙したら 13,523px | 記事ごとの点の地図へ（R2） |
| 空席のモヤが「小さな星」「破線の円」「引っかき傷」に見えた（3回失敗） | 広く散らす・向きを揃えない・粒は画面上で短いまま・半径は平方根で配る |
| ダークの金が DOM と canvas で2色あった | 1色に統一してテストで固定 |
| ライトで線が沈んで消えた | `alphaGain 1.6` と `glow` の引き下げ |
| カードの下の行が押せてしまった | 背面に覆いを敷く |
| sticky の位置を定数で書いて 22px の隙間 | ヘッダーと目次を実測 |
| トレイの幅を固定値にして点がはみ出た | `ResizeObserver` で実測、測れるまで描かない |
| 「明るさ＝記憶の残り」が実装では逆（忘れるほど明るい）だった | `0.5 + 0.45 × 保持力` に直した |
| 信号の芯がライトで細く淡かった／侵入の異物が円の枠を突き破っていた／多臓器障害の紋章が止まって見えた | ブラッシュアップ7件で個別に手当て（2026-09-05） |

## 11. 触るときの申し送り（codex へ）

1. **点の見た目・並び・文言を部品の中で計算しない。** `dex.ts` などの純関数を直し、部品は写すだけにする（テストが DOM を持たない作りなので、部品に判断を置くと検証できなくなる）
2. **金・書体・パレットは1か所。** DOM 側と canvas 側の両方に同じ値が要るものはテストで固定してある。片方だけ変えない
3. **sticky・トレイ・紋章の大きさに固定値を戻さない。** 実測している理由が上の表にある
4. **動きを足したら `reduced` の経路も足す。** canvas と JS の慣性は CSS の全体規則では止まらない
5. **「定着」と書かない・面を塗らない・金を離れかけ以外に使わない。** この3つは設計書の決定事項
6. 見た目を変えたら `/dev/recall-screen`・`/dev/recall-field` を **Python の playwright** で撮る（ライト・ダーク・スマホ幅）。Node 側の playwright は入っていない
7. 決定を変えたら設計書に**日付つきで書き足す**（このリポジトリの作法。惑星設計書の決定9〜14 が実例）
