# 知の蔓（仮）v1.1 — 筆の豆の木 システム設計（2026-08-01）

v1「知の塔」実機フィードバック（オーナー）と同日の設計議論の結晶。**実装方法の詳細検討は別セッションで行う**——この文書はそのための「何を作るか」の確定事項集。

## 0. 一言でいうと

**筆で描かれた豆の木が、鳥獣戯画の世界の実物たちを、グイーンと追い越していく背比べゲーム。**
学び（読んだ・書いた・即答できた・磨き直した）が葉になり、蔓が伸び、テントウムシ→湯のみ→スズメ→ネコ→…→東京タワー→富士山を越えていく。

## 1. v1からの変更の核（オーナー実機FBより）

| v1の問題 | v1.1の答え |
|---|---|
| 見た目・演出がイマイチ（ピル3本+白カード2枚） | 器を**筆の豆の木**に全面刷新。アートはAI生成の筆致アセット |
| 単位が混線（6.3cm/63歩/第2巻が同居） | **絵に実在する単位だけ**：cm（高さ=状態）と葉（枚=行為）。「歩」はUIから消し内部台帳の語に |
| 富士山に一生届かない（1歩=1mm線形） | **複利成長**：序盤実寸→ネコ(300)以降加速。「学びは複利」を機構で語る |
| 湯のみが図鑑の飾りで比較にならない | **背比べ構図**：次の実物が蔓の隣・同じ地面に実寸で立つ |

## 2. 確定した設計（議論済み・変更には再議論が要る）

### 2.1 世界観・アート
- **鳥獣戯画×ジャックと豆の木**。墨の筆線・かすれ・淡彩・和紙・朱。
- **スタイルアンカー**：オーナーがChatGPTで生成した4枚のうち**1枚目・4枚目系**（線が軽い・余白が多い・淡彩）。⚠️**この4枚の原画像はまだリポジトリに無い**——オーナーの端末/ChatGPTスレッドにある。次セッション最初のタスク＝`docs/superpowers/specs/assets/style-anchor/` に保存してもらう。
- 生きているもの（蔓・葉・住人動物）＝筆の絵。**計測だけは朱筆**（学者が巻物に入れる朱の書き込み＝「いま6.3cm」「あと3.7cm」の点線・寸法線・刻み）。
- 落款「知」。禁止語彙（制覇/マスター/コンプリート/枯れ）・音なし・ポイント/ガチャ/ストリーク禁止はv1から不変。

### 2.2 画面構成（背比べ）
- **同じ地面**に蔓と「次の実物」が実寸比で立つ。いまの高さの**朱の水平点線**が実物の胴に**刻み**を入れる（柱の背比べ）。縁までの残りは朱の寸法線「あと3.7cm」。
- 越えてきた実物は足元に薄い筆線で残る（テントウムシがキャップに乗る等の遊び）。
- その次の実物（例スズメ）は上空の段で淡く待つ。遠い夢（キリン5m・東京タワー333m・富士山3776m）はヘッダ下に活版の一行。
- **カメラ縮尺は常に「次の実物」に合わせる**——相手がゾウでも富士山でも同じ構図が成立する。
- ヘッダ：`いま 6.3cm ｜ 今週 葉が 12 枚`。見出しは直近の達成（「テントウムシを越えた」）。
- 葉の3状態：**青葉**=ナレッジ（いま即答できる）／**色褪せ**=要再確認／**輪郭のみ**=読んだだけ。**節**=葉30枚の結び目（朱の環）・タップで中身一覧（v1の巻めくりを継承。「巻」という語は廃止）。

### 2.3 成長曲線（複利）
- 序盤は実寸に正直（1歩=1mm、アリ3mm=3歩の一致を守る）。**ネコ（300歩=30cm）から複利加速**。
- 例示パラメータ（1%/歩）：ヒト≈470歩・東京タワー≈1000歩・**富士山≈1250歩（2〜3年圏内）**。
- ⚠️曲線パラメータは**表示に露出した後は実質変更不可**（ユーザーの高さが巻き戻るため）。**GA前に監修・確定**する調整可能定数として実装する。
- 魔法は成長速度の1箇所だけ。**目盛りの実物の寸法は実寸のまま嘘をつかない**。

### 2.4 データ・ロジック（v1資産をそのまま使う——無傷）
- 台帳 `tower-steps.ts`（段階遷移のみ積む・repolish日単位・「まだ→覚えた」連打対策）／`recallKind`／`tower-flags.ts`（暗転ゲート=earlyAccess）／`tower-backfill.ts`（mode:'recent'）／イベント配線（リーダー開閲・クイズ2箇所・passive ingest）／vitestテスト群。
- **変わるのは描画層（TowerStack/TowerCard/TowerScreen）と文言だけ**。高さ計算に複利カーブ関数が1本加わる（純関数+テスト）。
- ホームカード文面：`🌱 6.3cm ・ 湯のみまで あと3.7cm`（+1の瞬間は葉が1枚ひらくpop）。

## 3. アート制作パイプライン（3並列調査で検証済み・2026-08-01）

### 3.1 静止アセット（45〜55点・10〜16時間・$0〜30）
- **ChatGPT単一スレッド継続生成**（スタイルアンカー4枚+採用済み素材を毎回添付し直す）。画風ドリフトが出たら**Flux LoRA学習**（4枚から・約$4/20分）に切替える保険。
- **単色（生成り）背景で生成**→紙テクスチャは焼き込まない→**BiRefNet-matting**で透過抜き（筆のかすれ・淡彩＝ソフトエッジを保持できる唯一系。remove.bg等のハードカットはNG）→Photoshop Refine Edgeで仕上げ。
- **蔓は超縦長1枚を作らない**。「短・中・長」3段階を別生成（縦長一発は破綻しやすい／段階ごとに筆致を変えられて自然）。
- 内訳：蔓3段階・葉シート（3状態×形違い）・住人15体（テントウムシ〜富士山、主要数体は2ポーズ）・雲2-3・紙1-2。
- 発注書テンプレ（STYLE LOCK/CANVAS SPEC/NEGATIVE付き）は調査レポート済み——実装計画セッションで清書。

### 3.2 動き（3層アーキテクチャ）
1. **日常の+1**（毎日起きる）：静止マスターのCSSマスク微伸長＋葉ポップ。ソフトな筆の境界は**アセット側の先端アルファに焼き込む**（ランタイムでSDF計算しない）。葉/住人の反応は**Rive**（$9/月・ラスターメッシュ変形+データバインディング、iOS実測は要PoC）または2ポーズPNGクロスフェード。
2. **節目のグイーン**（目盛り越え・段階遷移）：段階画像2枚を**Start/End Frame**で繋ぐAI生成の**区間動画**。墨絵/イラスト系に強い一次情報があるのは**Kling**と**Hailuo(MiniMax)**。透過は**Runway背景除去→HEVC-alpha(iOS)/VP9-WebM(他)**の実証済みワークフロー。再生は`play()`→`ended`で静止画に着地する**ディスクリート方式**（iOS Safari PWAでのcurrentTime連続スクラブはフレーム精度が信頼できない——検証済みにつき不採用）。
3. **計測**：朱筆の数字・点線・刻みはコードのDOM/SVG（データの正確性はここが担保）。

### 3.3 コスト・工数見積（調査より）
- 静止アセット $0〜30＋10〜16h／区間動画 ¥5,000〜20,000＋0.5〜2日／Rive $9/月。

## 4. 未検証リスク（次セッションの最初の検証項目）
1. **最重要**：スタイルアンカーの画風のまま蔓が伸びる動画が出るか（Kling/Hailuoに1枚入れて5秒×各1回・数百円・30分。プロンプト「the vine grows upward slowly, ink wash painting style, no 3D shading, preserve brush texture, camera static」）。崩れたらMidjourney Video追試→全滅なら動画層を諦めCSS/Rive層のみで成立させる（設計はその撤退が可能な3層分離になっている）。
2. Rive Web runtimeのiOS Safari PWA実測（fps/メモリ）。ダメなら2ポーズPNG方式へ。
3. HEVC-alphaのiPhone実機（PWAモード含む）再生確認。
4. 複利カーブのパラメータ監修（オーナー）。

## 5. スコープ切り（v1.1 / 後回し）
