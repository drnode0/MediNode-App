# 体験終了アンケート（exit survey）設計書

日付: 2026-08-12
ステータス: 設計承認済み・実装計画待ち

## 背景と目的

プレミアム体験が終了する場面（無料トライアル失効・有料解約）で、離脱理由を聞く仕組みがない。
無料トライアル終了には既存の体験終了オーバーレイ（`TrialLifecycleNotice`）があるが外部フォームへのリンクのみ。
有料解約はStripeポータルへのリンクアウトで完結し、アプリ内には解約後のフックが一切ない。

このアンケートで知りたいこと（承認済みの4軸）:

1. 継続しなかった理由
2. 何があれば継続したか
3. 体験の満足度・良かった点
4. 復帰の可能性・条件、および**プレミアムでなく無料の個人利用としては使い続けたいか**

## 設問（4問＋自由記述・全問任意）

| # | 設問 | 形式 | 選択肢 |
|---|------|------|--------|
| 1 | 続けなかった一番の理由 | 単一選択 | 価格が合わない／収録内容が足りない（診療科・テーマ）／使う場面がなかった／検索・アプリの使い勝手／無料機能で十分だった／その他 |
| 2 | あと何があれば続けたか | 複数選択 | 自分の診療科のコンテンツ／もっと安いプラン／今日の1問などの習慣機能／職場の仲間と使える仕組み／特にない／その他 |
| 3 | 体験全体の満足度 | 星スケール | 既存 `SATISFACTION_SCALE` を流用 |
| 4 | これからのMediNode | 単一選択 | 無料のまま使い続けたい／条件が合えばプレミアムに戻りたい／たまに開くかもしれない／たぶん使わない |
| 5 | ひとこと（復帰の条件など） | 自由記述 | 任意・placeholder「復帰の条件や、ひとことあれば」 |

- 設問4が「個人利用として使い続けたいか」の直接の観測点。無料リテンション見込みと復帰候補を1問で切り分ける
- 「たぶん使わない」「特にない」の逃げ道を必ず残し、回答を歪めない
- 文言の最終調整は実装時に行ってよい（設問の意図と選択肢の骨子は変えない）

## 表示トリガー（3時点・すべて一度だけ）

| 時点 | 検知 | 出し方 |
|------|------|--------|
| 無料トライアル終了 | 既存 `classifyTrialLifecycle() === 'ended'` | 既存の体験終了オーバーレイに「1分アンケートに協力する」ボタンを追加 |
| 有料の解約予約 | `/api/premium/status` の `cancelAtPeriodEnd === true` | 設定画面の「解約手続き済み・◯/◯まで利用可能」表示直下に常設ボタン＋ホームに控えめバナーを一度だけ |
| 完全失効 | 未回答のまま `status === 'canceled'` | 失効後の初回起動でバナーをもう一度だけ |

### ゲーティング

- 回答済み: `medinode_exit_survey_done`（localStorage）
- バナー却下: `medinode_exit_survey_dismissed`（localStorage・時点キー付き。解約予約時と失効時で別々に一度ずつ）
- 端末をまたぐ厳密な重複排除は追わない（YAGNI）。同一端末で二度促さないことだけ保証する
- 「うるさくしない」原則: バナーは既存 `FeedbackNudgeBanner` と同等の控えめトーン。全画面を新設しない

## 実装構成

### クライアント

- `FeedbackModal` に kind `exit` を追加（bug/request/praise と並列）
  - exit のときは既存の任意4問アンケートの代わりに上記の設問セットを表示
  - 自動コンテキスト（会員種別・画面・バージョン・端末）は既存の「送る情報」開示つきでそのまま付く
- `TrialLifecycleNotice` の ended オーバーレイにアンケートボタンを追加（既存の外部フォームリンクは置き換え）
- 解約予約・失効の検知は `/api/premium/status` の既存レスポンス（`cancelAtPeriodEnd` / `status`）を読む。新API不要
- ホームの控えめバナーは既存バナースタック（`AppBanners.tsx` 系のパターン）に追加

### サーバー

- `/api/feedback/submit` の kind 許可リストに `exit` を追加し、専用フィールドのバリデーションを `feedback-submit.ts` に追加
- 送信経路・IPレート制限・Notion書き込み（`FEEDBACK_NOTION_TOKEN` / `FEEDBACK_DB_ID`）は既存をそのまま使う
- Supabase migration なし

### Notion（継続フィードバック_DB）

セレクト/マルチセレクトのプロパティを追加（既存プロパティは触らない）:

- 離脱理由（select）
- あれば続けた（multi_select）
- 今後の利用（select）

満足度・会員種別・自由記述は既存プロパティを流用。プロパティ追加はNotion MCPで実施（選択肢リネーム不可などのDDL制約は既知。新設のみなので影響なし）。

## テスト

- 表示ゲーティングを純関数に切り出してユニットテスト
  - trial ended／cancelAtPeriodEnd／canceled／回答済み／却下済みの各分岐
- `feedback-submit` のバリデーションテストに exit 種別を追加（必須なし・選択肢の値検証・自由記述の長さ上限）

## スコープ外

- メール・push でのアンケート依頼（アプリ内で完結、が要件）
- /admin での集計画面（回答はNotionで読む）
- 端末をまたぐ回答済み同期（user_metadata 等への記録）
- 回答に応じた引き止めオファー（クーポン等）— 将来の拡張余地としてだけ残す
