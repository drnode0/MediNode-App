## この設計が扱うこと

オーナーが `/admin/spread-edit` で実際に1本組んだときに出た、3つの使いにくさを解消する。

1. 追加した部品を移動できない
2. 新しく打った文が「原本にない」と赤くなり、言い回しを少し変えることすらできない
3. 各節に出す表やグラフを選ぶ手順が無い

3点とも、スプレッドの設計思想（本文は原本の逐語・中身はオーバレイに写さない）を
変えずに直せる。**思想は1つも緩めない**というのが、この設計の前提である。

## 変えない前提

| 前提 | 理由 |
|---|---|
| 逐語照合の関数そのもの | ここを緩めると、読者に出る医学本文が原本と食い違う経路ができる |
| 原本の表の中身をオーバレイに写さない | 原本を直したときに黙って古くなる。`tableFocus` / `partTitles` が別口である理由と同じ |
| 保存を止める条件は「間違いが読者に出るもの」だけ | 逐語一致・文献の取りこぼし・指す先を失った参照の3つ |
| サイズの自由指定は持たない | 完成度＝パイロット準拠の統一が目標 |

## 決めたこと

### 決定1: 逐語検査は緩めず、逃げ道を全部の欄に配線する

赤くなった欄の横に出る「この文をスプレッドノートに追加」を、節の部品の全欄と参考文献の欄にも出す。
押すとNotionの非公開ノートに1行入り、照合先が広がって赤が消える（理解チェックの今の挙動と同じ）。

`onAddToNotes` を `OverlayBuilder` → `SectionEditor` → `PartForm` → `InlinesEditor` / `VerbatimInput`
まで通す。`InlinesEditor` には受け口が無いので新しく足す。**足すのは、つないだ文全体を1行として
ノートへ送るボタン**（文節単位ではない。照合の単位が連結テキストのため）。

検査そのものは1文字も変えない。書き換えた文言が非公開ノートに全部残るので、あとで原本へ戻すかどうかを
見て決められる。

**却下した案**: 語尾や句読点の揺れを許すよう検査を緩める案。「どこまでが揺れか」を機械が決めることになり、
原本と食い違う文が黙って読者に出る経路ができる。

### 決定2: 節の中では、主役も含めて1本の並びとして上下に動かす

上下ボタンを主役にも付ける。追加の先頭で「上へ」を押すと主役と入れ替わる。
データの形（`parts[anchor]` が主役1つ、`extraParts[anchor]` が配列）は変えず、入れ替えは
主役と `extras[0]` の交換として書く。

主役が「自動判定」のまま（`parts[anchor]` が未設定）のときは、その表を追加の列に降ろせない。
原本の表の中身をオーバレイに写すことになるため。このときは上ボタンを無効にし、
**「先に主役を置き換えてください」と理由を1行出す**。黙って効かないボタンにはしない。

**却下した案**: 節をまたぐ移動（切り取り・貼り付け）。部品の中の文はその節の原本から選んだものなので、
別の節に貼ると中身が合わず結局作り直しになる。労力に見合わない。

### 決定3: 原本の表・図を選ぶ部品を新設する

部品の追加メニューに「原本の表・図」を足す。選ぶと、その節の中にある表と画像が候補として並び、
1つ選ぶと表層に出る。表は先頭行、画像はキャプション（無ければ順番）で見分ける。

保存されるのは**Notionのブロックの番号だけ**で、中身は写さない。原本の表やグラフを直せば表層も追いつく。

付随して決めた3点。

- **折りたたみからは消す。** 表層に上げたブロックは深掘りから除く。表を主役に上げたときの
  今の挙動（`sectionDisplay` の `dropTable`）と揃える。同じものが2回出ないため
- **指す先が消えたら保存を止める。** 別のブロックに当てにいくと読者に違う図を出す。
  参考文献の「指す先を失った圧縮行」と同じ fail-closed
- **描画は既存の部品を使う。** 折りたたみの中で画像・表を出しているのと同じ経路（`RenderedBlocks`）に
  そのブロック1件を渡す。新しい見た目は作らない

この部品は文字列を持たないので、逐語照合の対象には入らない（自動的にそうなる）。

**却下した案**: 節の中の表と画像を全部そのまま自動で表層に上げる案。出したくない図まで出る。
オーナーの言葉が「選択する手順がない」なので、自動で増やすのではなく選べるようにするのが要望そのもの。

### 決定4: 表に出すものの一覧を、編集画面の一番上に常設する

節を縦に並べ、各節について「今、表に出ているもの」を1行で出す。原本にある表・画像は候補ボタンとして
その場に並べ、押せばそのまま置ける。行をクリックするとその節の編集枠へ飛ぶ。

**「未決」の判定はひとつだけ**: その節の主役をまだ決めていない（`parts[anchor]` が未設定）。
「表層なしにする」を選べば決定ずみに変わる。

表層は、節を開かずに読める唯一の場所である。ここに置くのは主要な数値か押さえどころで、
細かい数値と原文の主張は折りたたみに残す。この一覧は、その判断を節ごとに1回ずつ通すための場所。

**却下した案**: 保存の直前の別画面にする案。編集に戻りたくなったときの行き来が増える。
常に上にあって未決が数字で出ていれば、取りこぼしを防ぐという目的には足りる。

### 決定5: 未決の節が残っていても保存できる

保存ボタンの横に「未決 2節」と数字で出すところまでにして、判断はオーナーに残す。

止めない理由: すでに作ってある記事は主役を明示していない節を持つので、止めるとその場で全部保存できなくなる。
また、逐語一致と文献の紐づけは「間違いが読者に出る」ので止めるが、未決は間違いではなく手つかずであり、
性質が違う。

## テストで固定すること

コードの振る舞いは実物を通して確かめる（自作データ同士の比較にしない）。

| 何を | どう |
|---|---|
| 主役と追加の入れ替え | 入れ替えたあとの並びが期待どおりで、主役が自動判定のときは交換が起きない |
| 新しい部品の sanitize | ブロックIDが無い・文字列でない部品は落ちる |
| 深掘りからの除去 | 表層に上げたブロックが深掘りに残らない。上げていないブロックは残る |
| 指す先を失った参照 | 原本からそのブロックが消えたスプレッドで、保存の関門が落ちる |
| 逐語照合 | この作業で1件も挙動が変わらない（既存のテストが全部通る） |
| 未決の数え方 | 主役未設定の節だけが数えられ、`none` を選んだ節は数えられない |
