# Recall｜「振るい落とす」機構 壁打ち用ブリーフ

2026-09-03 作成。**新しいセッションで、この機構だけに集中して壁打ちするための資料。**
実装計画ではない。決めるべきことを並べただけの紙。

---

## やりたいこと（オーナーの言葉）

> 物理学的にも美しく回転させたり、ジャイロで傾いたり、クルクルと回すとかのアクションで、
> 習得率の低い知識が振るい落とされる。その知識がクイズになる。

つまり **「今日はどれを復習するか」を、ボタンではなく手の動きで決める。**
球を回す・傾ける・揺するという物理の操作そのものが、復習する主張の選定になる。

---

## なぜ先に絵を決めようとして3回失敗したか

見た目を9案・36案と出して、どれも決め手を欠いた。原因は順番。
**「振ると外れて落ちる」なら、主張は「表面に付いていて、取れるもの」でなければならない。**
この条件だけで、出てきた案の大半（地層・流域・編み物・ステンドグラス・光場・雪原）は失格になる。
残るのは、葉・実・鱗・結晶・砂・水滴のように「付いていて、落ちる」もの。

機構が決まれば、絵の候補は勝手に絞られる。だから機構が先。

## いま動いているもの（作り直さなくていい）

本番稼働中。`src/lib/recall/` と `src/components/recall/`。

| あるもの | 中身 |
|---|---|
| 主張の実体 | 687件（27記事・15分野）。`recall_claims` に保存済み。毎晩の同期で更新 |
| 状態4段階 | 未着手 / 読んだ / 残した / 覚えた（`stateOf`） |
| **保持力の数値** | `remainingOf` = 1 − 経過日数 ÷ 間隔日数。**1が満タン、0が期限切れ**。時間で必ず減る |
| 間隔反復 | 正解で 1→3→7→14→30→60→120→240→365日、不正解で1日に戻る（`applyResult`） |
| **落とす候補の選定** | `pickCandidates`：保持力 < **0.28** のものを、低い順に最大**5件**（`ESCAPE_THRESHOLD` / `MAX_CANDIDATES`） |
| **落ちる演出** | 選ばれた主張が弧を描いて画面下の「山」へ飛ぶ（`drawFrame` の `flying`）。着地後はタップで開ける |
| 落ちかけの表示 | 保持力が0.28を割ると明滅する（`isFading`）。用語も既に「離脱」で書かれている |
| クイズ本体 | `RecallCard`。伏せ字の穴あき問題→「覚えた／まだ」で `applyResult` |
| 配置 | 主張を足しても既存が1つも動かない（席→記事→らせん）。記事ごとに枝で繋がる |
| 動きを減らす設定 | 対応済み。ゆらぎ・明滅・弧を止める |

**つまり「落ちる・溜まる・クイズになる・間隔が伸びる」は全部もう動いている。**
いま足りないのは、**それを起動するのがボタンだということ**（画面下の「確かめる」）。

## この機構のために新しく要るもの

1. **手の動きを読む**：回す速さ、傾き（ジャイロ）、揺すり。
   - iOS Safari は `DeviceMotionEvent.requestPermission()` の明示許可が要る。**ユーザーの操作がないと許可を求められない**
   - PC には傾きが無い。マウスでの代替が要る
2. **落ちるかどうかの物理**：保持力の低いものほど外れやすい、を数式にする
3. **落ちたあとの球**：穴が空くのか、閉じるのか、戻ってくるのか
4. **誤爆しないこと**：歩きながらポケットの中で全部落ちる、が起きない設計

---

## 決めること（この順で壁打ちする）

### 1. 物理は「選定」か「演出」か ← 最初にこれ
- **A案：物理が決める。** 揺すった強さと保持力で、落ちる／落ちないが実際に決まる。
  気持ちいいが、**毎回の結果が違う**。0件のことも30件のこともある。復習の設計としては暴れる
- **B案：`pickCandidates` が決め、物理は見せ方。** 落ちるのは常に保持力の低い最大5件。
  再現するが、「自分が振って落とした」感が薄れる
- **C案：確率。** 落ちる確率 = f(保持力, 揺すった強さ)。上限だけ決める（1回5件まで等）

*いまのコードはB。オーナーの言葉（「振るい落とされる」）はA寄りに読める。ここが分岐点。*

### 2. 1回で何個落ちると気持ちいいか
いまは5件上限。振る動作なら3件でも10件でもありうる。**1回の復習を何分で終わらせたいか**から逆算する。

### 3. 落ちたあとの導線
落ちた山 → 1件ずつクイズ → 正解なら？ 不正解なら？
- 正解＝球に戻って光る／不正解＝山に残る、が素直
- 全部答えないと球が欠けたまま、にするか（強制力は諸刃）

### 4. 落ちた跡をどうするか
球に穴が空いたままなら「やり残し」が一目で分かる。**これは強い**。
ただし欠けた球は見た目が汚い。跡を残すか、閉じるか。

### 5. 起動のジェスチャー
- 揺する（加速度）／速く回して止める（角速度）／傾け続ける（重力）
- **どれも誤爆する。** 明示的な入口（ボタン）は残すのか、それとも動きだけにするのか
- 動きを減らす設定の人には別の入口が必ず要る

### 6. ジャイロの許可をいつ求めるか
初回に出す／振ろうとした瞬間に出す／設定から。**断られたときも使えること**が条件。

### 7. 保持力を画面でどう見せるか
落ちる前に「これは落ちそうだ」と分かる必要がある（分からないと理不尽）。
いまは明滅。揺れ幅・傾き・色のどれで見せるか。

### 8. 「今日の1問」との関係
既存機能。振るい落としが復習の入口になるなら、あれは要るのか。
*前セッションで「Recall公開とは切り離す」と決めた件。ここで再検討ライン。*

## 機構から自動的に決まる、絵の条件

機構が決まったあとに絵を決める。そのとき最初から効いている縛りは4つ。

1. 主張は**表面に付いている**もの（付着物）。地層・流域のような「面そのもの」は不可
2. **外れて落ちる**動きが自然なもの。落ちて溜まったときも形が保つもの
3. 保持力が**外から見える**もの（付き方の浅さ・揺れ・色）
4. 687個が付いていて、なお静かに見えるもの
