# サブスクDB 本文アプリ内レンダラ＋ギャラリー（公開URL抜け道の封鎖）— 設計

- 登録日: 2026-07-22
- 対象範囲: アプリ / Notion
- ステータス: spec化済
- 優先度: 高

## 1. 背景と問題

MediNode のプレミアムは、オーナー（筆者）の Notion「🩺 Medical Knowledge_DB（サブスク用）」を **Web公開（publish to web）** した上で、アプリ内カードの「Notionで開く」で各ページ（`notionUrl` = 公開 `notion.so` URL）に飛ばして全文を読ませている（現状: `src/components/ResultCard.tsx` の `hit.notionUrl` リンク、本文はアプリ内に描画せず外部Notionで閲覧）。

このため次の**抜け道**が構造的に存在する:

- 公開された Notion **DBのURL**は「全ページ一覧＋新規追加が自動で載る＋認証なし＋URL固定」。
- プレミアム会員が DB URL（または各ページURL）を保存し、**解約後もオーナーのDBを継続閲覧**できる。しかも新規ナレッジまで見え続ける（蛇口が開きっぱなし）。

根本原因は **Notionの「Web公開」が全公開/非公開の二択で、"会員だけに公開"が存在しない**こと。ページ単位公開に変えても「保存できる公開URL」は残るため、限定的な漏れ（在籍中に開いたページ）は消えない。

## 2. 解決方針（確定）

**アプリをギャラリー本体＋本文リーダーにし、サブスクDBを非公開の裏DB化する。** 世の中に「保存できるURL（DBもページも）」が存在しない状態を作る＝漏れゼロ。

- サブスクDBの本文は、アプリのサーバーが **pageID から統合トークンで生ブロックを取得**し、**プレミアム会員セッションを検証した時だけ**アプリ内に描画する。公開URLは作らない。
- ギャラリー（ジャンル別・カード・現場の疑問）は**既存の `GenreBrowse` を拡張**（Algolia由来の一覧に**カードサムネ**を追加）。
- アプリがNotion閲覧体験を完全代替できた段階で、**サブスクDBのWeb公開をOFF**にする（無傷移行。巻き戻しは再公開するだけ）。

### スコープ境界（重要）

抜け道は「**オーナーの資産を、他人（有料会員）に公開している**」サブスクDB**だけ**の問題。以下は**現状維持**する。

| データソース | 中身の持ち主 | 読み方 | 理由 |
|---|---|---|---|
| **サブスクDB** | オーナー（他人に配る） | **アプリ内で読む（本spec）** | 公開＝抜け道。ここだけ塞ぐ |
| 個人DB | ユーザー本人 | 現状維持（Notionに飛ぶ） | 自分のNotionを自分のトークンで読む。公開しておらず穴なし |
| 部署DB | 組織 | 現状維持（Notionに飛ぶ） | 組織のNotionを組織のトークンで読む。オーナー資産の漏れではない |

同じレンダラは将来、見た目統一のため個人/部署にも流用可能だが、**セキュリティ上の必要はない**（v1では対象外）。

## 3. アーキテクチャ

### 3.1 ギャラリー（discovery）
- 既存 `src/components/GenreBrowse.tsx`（サブスク対応済み・Algoliaヒット→`ResultCard`）を土台にする。
- 現状の同期（`src/app/api/subscription/sync/_core.ts`）が Algolia に載せているのは title / 要約 / 見出し / ジャンル / キーワード / `hasAttachment` / `notionUrl` 等。
- **追加**: カードサムネ用に**先頭画像（またはカバー）のNotion画像参照**を同期対象に足す。Notion画像URLは署名付きで失効（~1h）するため、URLそのものではなく **pageIDから読み直せる形**（画像ブロックID or カバー参照）を持ち、表示時にサーバーが署名URLを取り直す。
- カードの `notionUrl` 直リンクは、サブスク（`owner === 'subscription'`）では**アプリ内リーダーへの内部遷移に置き換える**（`notionUrl` は保持するが、Web公開OFF後は表示に使わない）。

### 3.2 本文リーダー（新規）
- 新規サーバールート（例: `src/app/api/subscription/page/[pageId]/route.ts`）:
  1. **プレミアム会員検証**（サーバー側）。`src/app/api/premium/verify/route.ts` と同じ判定ロジック（サブスク状態）を共有し、非会員には 403。クライアントを信用しない。
  2. **オーナーの統合トークン**（サブスク同期で既に server env に存在するトークン）で、`blocks.children.list` を pageID から取得（トグル/カラム等はネストを再帰取得）。
  3. **ハウス書式のブロック語彙**だけを描画用の構造化JSONに変換して返す（下記 3.4）。**逐語**（要約・言い換えをしない）。
- クライアント: 返ってきた構造化JSONを、MediNodeの配色・ダークモードに合わせた**リーダーコンポーネント**で描画。確信度マーク（✅⚠️❓）は色分けされた**タップ可能な出典リンク**、本文中リンクも生きる。画像は**タップで全画面ズーム**。

### 3.3 鮮度とキャッシュ
- **本文は同期を待たない**。カードを開いた瞬間に pageID で生取得するため、**Notionで保存した版が次に開けば反映**（実質リアルタイム）。
- 性能のため、サーバー側に **`pageId` + `last_edited_time` をキーにした短期キャッシュ**（TTL 数分）を噛ませる。`last_edited_time` は Algolia 同期済みなので、編集でキーが変わり自動失効。Notion API のレート制限（~3 req/s）はキャッシュで大半を吸収。
- **ギャラリーのメタ（title/要約/見出し/サムネ参照）は既存の subscription-sync 周期で更新**（`src/app/api/cron/subscription-sync/route.ts`）。

### 3.4 対象ブロック語彙（ハウス書式）
レンダラは以下を対象にする。これがサブスクナレッジの実書式（本CQ実例で確認済み）:

- `heading_1` / `heading_2`（番号付きH2セクション）
- `paragraph`（rich_text: 太字・インラインリンク・確信度マーク絵文字を含む）
- `bulleted_list_item` / `numbered_list_item`
- `callout`（アイコン別スタイル: ⚡この問いへの答え / 🧑‍⚕️実践 / 🤖査読 / 📚文献 / ⚠️注意。`color`（yellow_bg/green_bg/gray_bg）でトーン分け）
- `image`（本文画像・カバー。署名URLを表示時に再取得）
- `divider`
- `table`（日本運用の作り方表など。まれ）

**契約**: 筆者はこの語彙内で執筆する（今の書き方のまま）。奇抜なNotionブロック（synced block・複雑な埋め込み等）を増やさない限り破綻しない。未対応ブロックは**素朴なテキストフォールバック**で落とさず表示する。

### 3.5 セキュリティモデル
- 公開URLを一切作らない（DBもページも）。抜け道の物理的消滅。
- リーダールートは**読むたびにサーバー側で会員判定**。非会員は本文を取得できない。
- 統合トークンは **server-side のみ**。クライアントに露出しない。
- 本文はサーバーを**一時的に通過**＋短期キャッシュのみ（永続保存しない）。キャッシュも会員ゲートの内側。

## 4. 見せ方＝第一級の目的（段階導入）

本文をアプリ内に持つ最大の戦利品は**構成と体験を自分で設計できる**こと（Notionページのままでは不可）。ただし**v1は忠実レンダに絞り**、作り込みはv2以降に一枚ずつ乗せる（最初から全部やると"重さ"が戻る）。

- **v1（本spec）**: 忠実レンダ＋会員ゲート＋ギャラリー（サムネ）＋画像ズーム。
- **v2以降（別spec/plan）**: ⚡答えの先頭固定TL;DR / 確信度マークで絞り込み / マークタップで出典その場展開 / ナレッジ相互リンク（低Na⇄低K）/ 用量タップで計算ツール / 読了・ブックマーク / 「今日の1問」から直行。

## 5. 移行手順（無傷）

1. **今**: サブスクDBは公開のまま（漏れは低EV: 信頼できる臨床家中心・件数少・1件=1サブスク）。既存の「Notionで開く」は当面残す。
2. アプリに **①サムネ同期 ②本文リーダー（会員ゲート）** を実装・デプロイ。サブスクカードの遷移をリーダーへ切替。
3. アプリがNotion閲覧を**完全代替**できたことを確認したら、**サブスクDBのWeb公開をOFF**。以降 `notionUrl` は表示に使わない。
4. 巻き戻しが要れば**再公開するだけ**（データ移行なし）。

## 6. Non-goals（v1でやらないこと）
- 個人DB・部署DBのアプリ内リーダー化（現状維持）。
- Notionの全ブロックタイプを網羅する汎用レンダラ（ハウス書式に限定）。
- 本文のリアルタイム共同編集・双方向同期（Notionが唯一の編集元）。
- v2見せ方機能（絞り込み・計算ツール等）。

## 7. テスト観点
- 会員ゲート: 非プレミアムセッションでリーダールートが 403 を返す。
- 逐語: 代表ナレッジ（低Na補正・低K補正）で、Notion原文の全セクション・数値・callout・確信度マーク・リンクが欠落なく描画される。
- 画像: 署名URL失効後もサーバー再取得で表示できる（時間をおいた再アクセス）。
- 鮮度: Notionで本文を編集→再オープンで新版が出る（キャッシュTTL内は旧版、`last_edited_time` 変化後は新版）。
- フォールバック: 未対応ブロックを含むページでもクラッシュせずテキスト表示。
- スコープ: 個人DB・部署DBの挙動が一切変わらない（回帰なし）。

## 8. Open Questions（実装計画で確定する）
- サムネの取得元: ページ**カバー**か**先頭 image ブロック**か（既存インフォグラの置き場に合わせる）。
- キャッシュTTLの具体値と実装場所（メモリ or KV）。
- リーダールートの会員判定を `premium/verify` と**共通関数化**する範囲。
- レート制限が問題化する規模の閾値と、その時の事前バルク取得の要否。
