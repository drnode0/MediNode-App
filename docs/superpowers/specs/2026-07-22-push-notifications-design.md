# プッシュ通知（Web Push）設計 — 2026-07-22

アプリを閉じている医療者を"外から"戻すエンジン。②「今日の1問」の相棒であり、毎日開く本命のリテンションレバー。
経緯・多視点レビュー（ブランド/マーケ/ゲーム/研修医/看護師）と序列見直しは別セッションの壁打ちを参照。

## 位置づけ・序列

- 毎日開かせる本線は **②今日の1問（即公開）→ 本機能（プッシュ）** のペア。XP/継続表示（④）は助演・ソロ試用。
- 本機能は「アプリを閉じている人を戻す動線」が現在ゼロである穴を埋める。今の"通知"はアプリ内バナー＋解決済みCQリストのみ（開かないと気づけない）。

## 確定仕様

- **チャネル**: Web Push（PWA）1本に絞る。VAPID方式。
  - iOS Safari はホーム画面に追加済み＋iOS16.4以降のみ到達。未インストール層に届かない穴は fast-follow（LINE補完）で別項。
  - 非対応ブラウザ／未許可／VAPID未設定 → 機能無効（アプリは通常どおり）。
- **通知の種類（v1=3種）**:
  1. **今日の1問（デイリー）**: 1日1通。送信時刻は**ユーザー選択制**（離散プリセット `07:00 / 07:30 / 08:00 / 12:30 / 20:00 / 21:00`、既定 `07:30` JST）。
  2. **解決済みCQ回答（イベント駆動）**: 自分が投稿/フォローしたCQに回答がついた時、その投稿者へ。希少。
  3. **お知らせ（手動ブロードキャスト）**: adminから購読者全員へ一斉送信。週1程度を上限の自主ルール。
- **頻度キャップ（静かなブランド）**: デイリー1通＋CQ回答（希少）＋お知らせ週1上限。連投しない。
- **オプトイン粒度**: **マスターON/OFF（全体）＋種類別トグル**（今日の1問／CQ回答／お知らせを個別にオフ可）の二段構え。「全部止めたい」も「お知らせだけ切りたい」も両対応。
- **可逆性（重要）**: アプリ内トグルを**主スイッチ**にする。オフ＝送信を止めるだけで購読データは保持 → **再オンはワンタップ**、OSの許可を聞き直さない。OS側で許可が取り消されている場合のみ「端末設定で通知を許可してください」と案内を出す。「一度切ったら戻せない」を作らない。
- **設計思想＝静けさ優先**: 「うるさい→開かれなくなる」を最大の自滅と位置づけ、控えめ頻度・保守的デフォルト・どこからでも即オフを貫く。オフ導線は常に1〜2タップで届く場所に置く。
- **許可プライマー**: 「今日の1問」を**初回回答した直後**に自前シート（「明日の1問を通知で受け取りますか？」）→OKで初めてネイティブ許可を呼ぶ。「あとで」はネイティブ許可を焼かない（後日再提示可）。
  - iOS未インストール検出時はプライマーを「ホーム画面に追加」案内へ差し替え。
- **段階公開**: app_flags の `push` 行に stage（off / preview / on）。preview対象は COMP_ADMIN_EMAILS ∪ PUSH_PREVIEW_EMAILS。切替は `/admin/maintenance` のカードから（デプロイ不要）。初期 off。
- **当面のゴールは preview（オーナー専用のお試し）**。当面は `on`（全員公開）へ進めず、自分のアカウントだけで使う。全員公開は使用感を見てから別途判断（④XP表示と同じ扱い）。他ユーザーには機能自体が現れない。
- **オフ**: マスターOFF／種類別トグル／OS側の許可取消のいずれでも停止。アプリ内OFFは購読を保持し再オン容易、OS取消は完全停止（再開は端末設定案内）。

## 送信の流れ

- **デイリー**: Vercel Cron（`*/30 * * * *`）→ `daily-push` エンドポイント → JST現在スロットに一致し「今日の1問」トグルON・当日未送信の購読者を抽出 → 各自へ送信 → 送信済みマーク（重複防止）。
- **CQ回答**: CQが解決フラグへ遷移する既存処理にフックを足し、投稿者の購読があれば送信。無ければ通知対象外にフォールバック（アプリ内リストには従来どおり出る）。
- **お知らせ**: adminフォームから件名/本文→全購読者（お知らせトグルON）へ送信。週1上限は運用ルール（UIに直近送信日を表示）。

## フェイルセーフ

- migration未適用・VAPID未設定・stage=off → `{ enabled: false }`（プライマー非表示・購読受付なし・アプリ通常どおり）。
- 送信はbest-effort（失敗しても機能は継続）。410/404は購読を `revoked_at` で掃除。
- ローカル動作確認用に env `PUSH_STAGE` がstageを上書き（本番Vercelでは未設定）。

## 依存・要確認

1. **②今日の1問が公開済みであること**（プライマーが②の初回回答直後に出るため）。序列どおり②公開が先。
2. **解決済みCQの「投稿者→アカウント→購読」紐付けが取れるか**は実装時に要確認。取れないCQはプッシュ対象外にフォールバック（既存のアプリ内通知は維持）。
3. ユーザー選択制のため cron はスロット離散化前提。自由分刻みは v2 以降。

## 個人データ・整合

- 購読はサーバー保存だが **user単位**（アカウント分離）。端末ローカルの許可状態フラグは `PERSONAL_DEVICE_KEYS` に登録（アカウント切替で漏れない）。
- 規約に1行: 通知は提供状況により遅延・不達がありうる／配信保証はしない。

## スコープ外（fast-follow）

- LINEによる到達補完（iOS未インストール層）。
- 連続リマインド通知（連続を主役から外した＋罪悪感トーンのため見送り）。
- 新着ナレッジ/筆者追加の自動プッシュ（頻度・スパム化リスクのため見送り。お知らせ手動で代替可能）。
- 送信時刻の自由分刻み・地域timezone対応。
