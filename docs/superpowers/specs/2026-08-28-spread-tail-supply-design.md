# 誌面の末尾整形と圧縮文言の供給

日付: 2026-08-28
状態: オーナー承認済み（会話で段階確認）
先行資料: `docs/superpowers/specs/2026-08-27-reader-spread-design.md`（誌面の本体設計）

## 背景・課題

誌面の最終目標はパイロット誌面の完成度である。節と部品はパイロットCSSの1対1移植まで
到達したが、記事末尾（署名ブロック・参考文献・免責）は共通レンダラ RenderedBlocks に
そのまま渡しており、誌面用の化粧が当たっていない。実機では署名ブロックがアプリ既定の
callout（丸アイコン＋薄い塗り）、参考文献の見出しが黄色の箱として出る。
これは既知の失敗形（共通レンダラの上に化粧する作りは、化粧し忘れた箇所が既定に戻る）の
残りである。

あわせて、パイロットが持つ圧縮文言のうち2点が本番では供給経路を持たない。

- 参考文献の1行説明: パイロットは「短いタイトル（略記の出典）1行説明」。
  本番は原本の完全タイトル＋巻号＋2〜3文の説明をそのまま出している。
- 理解チェックの解説文: パイロットは「正解：…」の書き下ろし。本番は根拠の逐語を出している。

圧縮文言は原本に無い（原本には公開リンクがあり、制作メモを置くと読者に見える）。
逐語一致検査の照合先は「原本＋非公開の誌面ノート_DB」に既に広げてあるため、
圧縮文言はノートDBに置き、オーバレイが構造として参照する。

## 決定事項

1. 末尾は表示専用の純関数で「実践（signature）／文献（evidence）／免責（disclaimer）」に
   分け、誌面が自前の枠で組む。分類は既存の `calloutRole` を使い、新しい判定規則を作らない。
2. 参考文献の圧縮行は `SpreadRef = { title, source, note }` として**オーバレイから供給**する。
   3つとも逐語一致検査の対象。オーバレイに無ければ現在の表示のまま落ちる（fail-safe）。
3. 理解チェックの解説文は `SpreadQuiz.explanation?` として供給する。逐語検査の対象。
   無ければ現在どおり根拠の逐語を出す。
4. 出典サマリの略記は**作らない**。酸素療法では原本の出典文字列が既に略記の形であり、
   差が出ない。再検討ライン: 出典文字列が長い記事を誌面化するとき、同じ仕組み
   （ノートDB＋オーバレイ）で足す。
5. 編集の入口はビルダー（`/admin/spread-edit`）。Claude がいなくてもオーナーが直せる形を保つ。
6. パイロット上部のブランドバーは**入れないと確定**する。ブランド名はアプリのヘッダー、
   凡例は追従目次バーと更新日行、テーマ切替は設定パネル、編集は /admin に既にある。
   再検討ライン: 誌面をアプリの外へ公開するとき、またはアプリのヘッダーを記事画面で隠すとき。

## 実装の段

### 段1 末尾の誌面化（供給不要）

`splitTailBlocks(rest: ReaderBlock[])` を `src/lib/reader-spread.ts` に足す。
戻り値は `{ practice: ReaderBlock | null; refsHead: ReaderBlock | null; refsItems: ReaderBlock[];
disclaimer: ReaderBlock[]; rest: ReaderBlock[] }`。分類できないブロックは rest に残し、
従来どおり RenderedBlocks に渡す（黙って消さない）。

ReaderSpread が3つを自前の枠で組む。CSSは `spread.module.css` にパイロットから1対1で移植する。

- 実践: 緑1.5px枠・角丸12px、見出しは緑tintの帯（`--brand-tint` / `--brand-deep`）。
  callout の丸アイコンは出さない。「※」で始まる行は上罫線＋0.75rem・グレー。
- 文献: 見出しは箱をやめて 0.95rem の素の見出し。項目は番号つき `ol`
  （padding-left 1.4em・0.85rem・グレー、太字だけ濃い色）。
- 免責: 上罫線＋0.78rem・グレー。

追従目次バーの凡例が目次チップに重なる不具合を同時に直す。

`.preview/style-diff.mjs` の PAIRS に practice / refs / disclaimer の3行を足し、差分なしを確認する。

### 段2 参考文献の供給

- 型: `SpreadRef`、`SpreadDoc.refs?`、`SpreadOverlay.refs?`（いずれも optional。
  保存済みの旧 SpreadDoc に無いため）。
- `sanitizeOverlay`: title が空の行を捨てる。
- `applyOverlay`: `refs` を載せる。本文には触れない。
- `verbatimTargets`: title / source / note を対象に足す。
- レンダラ: `spread.refs` があれば `ol` をそれで組み、原本の箇条書き（refsItems）は出さない。
- ビルダー: 「参考文献」欄（行の追加・削除・並び替え、3入力、その場の逐語検査で赤字）。
- 酸素療法の圧縮6行は Claude が草案を書き、誌面ノート_DB に入れて層2の判定を仰ぐ。

### 段3 理解チェックの解説文

- 型: `SpreadQuiz.explanation?`。`verbatimTargets` に足す。
- レンダラ: あれば「正解：…」として出し、無ければ現在どおり evidence を出す。
- ビルダー: 設問ごとに解説の入力欄（逐語検査つき）。

## 検証

- 逐語検査: ノートDBに無い文を refs / explanation に入れると保存が落ちること（テスト）。
- fail-safe: refs / explanation が無い誌面が現在と1文字も変わらないこと（テスト）。
- 見た目: `.preview/style-diff.mjs` が全ペアで差分なし。
- 実機: `/dev/spread` と実データのスナップショットで、可視テキストを上から順に突き合わせる。
