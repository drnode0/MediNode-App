# 文体ゲート（Claudeが書いた日本語を、掛けるたびに良くなる形で校閲する）

2026-08-30 設計確定。

## 背景

MediNode の本文と表示部品の日本語は Claude が書いている。いまはそれを Notion AI の
suggest edit に通すことで読みやすくしており、オーナーの評価も「suggest edit を通して読みやすくなった」
だった。この工程を、できる範囲で Claude 側へ寄せる。

既存の検証層では捕まらない。層2は数値と帰属、層3は原文照合、層2.5（`lexicon-lint.py`）は
語彙の辞書照合で、いずれも**文の型**を見ていない。実例として「発汗著明」→「著明な発汗」は
誤語でも比喩でも略語でもなく語順の問題で、辞書照合には原理的に当たらない。

## 正本

ルールの正本は Notion ページ **「✍️ 医療記事 文体の癖・校正パターン」**
（`668433e5611f42e9bbc44e975e6fdf16`）。

- 「現在の文体フィンガープリント」（残したい特徴・出やすい癖8カテゴリ）
- 「Before／Afterの基本パターン」
- 「追加ログ」（記事ごとの採用例）

**スキル・スクリプト側にルールを書き写さない。** URLを指し、実行時に `notion-fetch` で読む。
書き写すとページが育ったときに古い写しが残る（語彙表を📐共通規格へ一本化したのと同じ判断）。

## 対象

Claude が書いた日本語は3か所にある。3つとも対象にする。

| 対象 | いまの網 | 置き場所 |
|---|---|---|
| 原本の本文 | suggest edit（Notion AI）に依存 | Notion（My MEDICAL_DB / サブスクDB） |
| オーバレイの命名 | **無し** | アプリリポの `.preview/*-overlay.json` と `reader_spreads.overlay` |
| スプレッドノートの文言 | 逐語検査はあるが**循環している** | 🎨スプレッドノート_DB（非公開） |

3つ目の循環とは、参考文献の圧縮行と理解チェックの解説が `verifyVerbatim` を通るのは、
照合先のスプレッドノートも Claude が書いているからで、日本語としては誰も見ていないという意味
（`src/lib/reader-spread.ts` の `verbatimTargets` は refs の3文言をノート込みで照合する）。

### 命名の範囲

`verbatimTargets`（`src/lib/reader-spread.ts:526`）が集めないものが命名。実装時はここの裏返しとして
機械的に導出する。

- `comparison` / `matrix` の `title`
- `flow` / `timeline` の `step.label`
- `cards[].title`
- `gonogo.goLabel` / `noGoLabel`
- `gauge.title`
- `decision.question` / `branches[].when`
- `quizzes[].question` / `choices[]`
- オーバレイ直下の `shortLabels` の値 / `partTitles` の値

## 掛ける順番

```
原本を書く → 層3（原文照合）を反映
   ↓
【文章ゲート】語彙リンタ（既存）＋ 文体校閲（新設）
   ↓
原本フリーズ
   ↓
オーバレイを作る
   ↓
【命名ゲート】命名とスプレッドノートの文言を読む（新設）
   ↓
投入 → 理解チェックの承認 → 公開
```

**本文の校閲は必ずオーバレイより前**に置く。逆順にすると、原本の校閲が入った瞬間に
オーバレイの切り出しマーカーが落ちる（2026-08-30 に📚急性呼吸不全で12文が落ちて復旧作業になった）。

文章ゲートの位置は既存の決定に合わせ、**層2.5と同じ場所に同居させる**。層2.5は
2026-08-07 に「語彙は文章が最後に動き終わった後に通す。検査してから書き足す順番である限り
原理的に漏れる」という理由で位置が決まっている。文体も同じ性質なので同じ場所に置く。
**新しいゲートを別の工程点に増やさない**（二重にすると片方が形骸化する）。

## 承認の粒度

Notion ページの運用ルール3「医学的な意味が変わる修正と、日本語だけを整える修正を分けて記録する」を、
そのまま承認の重さに使う。

| 種類 | 例 | 承認 |
|---|---|---|
| 日本語だけを整える | 語順（発汗著明→著明な発汗）・冗長・助詞・命名の宙吊り | 一覧でまとめて承認 |
| 医学的な意味に触れる | 因果の断定を緩める・分母や対象集団を足す・単一指標での断定を外す | **1件ずつ承認** |

「NIVが失敗する」→「NIV開始後に改善がみられず、気管挿管を要する」は後者。読者に届く医学的主張が変わる。

**自動適用はしない。** 承認を経ずに原本を書き換えない。

## 道具

8カテゴリのうち、検出語で機械的に当たるのは3つだけ（「失敗」の多用／推奨表現／因果の断定）。
残る5つ（主語・対象の省略／単一指標への単純化／見出しの断定／節末要約の圧縮しすぎ／比喩・抽象表現）は
読まないと判定できない。**機械には候補出しだけをさせ、判定はモデルが読む。**
これは層2.5が既に採っている形（「リンタが拾えないものを目で読む」）と同じ。

### 1. `style-lint.py`

置き場所は `~/.claude/skills/medinode-factcheck/scripts/`（`lexicon-lint.py` の隣）。
**別ファイルにする。** `lexicon-lint.py` は「その語が存在するか」の辞書、こちらは「文の型」で、
混ぜると tier A/B/C の意味が壊れる。工程からは2本続けて呼ぶ。

- 入力は `notion-fetch` の本文全文を保存したファイル（抜粋を自作しない。既存の鉄則）
- 出力は行番号つきの候補。カテゴリ名は Notion ページの8カテゴリの名前をそのまま使う
- 📝背景callout と 🧑‍⚕️署名callout は既定で対象外（`lexicon-lint.py` と同じ）

### 2. `spread-namings.mts`

置き場所はアプリリポの `.preview/`。オーバレイJSON（または `--json` で書き出したスプレッド）から
命名を全部抜いて、種類つきの一覧にする。

- `verbatimTargets` の裏返しなので、**部品を足したらここにも足す**運用にする
  （`.preview/style-diff.mjs` の PAIRS と同じ扱い。設計上、追随漏れは起こりうる）
- スプレッドノートの文言（refs の3行と理解チェックの解説）も同じ一覧に出す。
  逐語検査は通っていても日本語は未校閲なため

### 出力の形

機械の候補出しとモデルの読みは、**1つの表に合流させる**（承認する側が2か所を見比べなくてよいように）。
1件は次の5列を持つ。ログへの追記もこの形をそのまま使う。

| 列 | 中身 |
|---|---|
| Before | 修正前の逐語 |
| After | 採用案 |
| カテゴリ | Notionページの8カテゴリの名前 |
| 修正理由 | 誤読リスク／医学的正確性／日本語の自然さ のどれか＋1文 |
| 種類 | `日本語` または `医学` （承認の重さを決める） |

`種類` が `医学` の行は1件ずつ承認する。`日本語` の行はまとめて承認する。

## 育てかた

Notion ページの運用ルール1・2を Claude が実行する。

1. 校閲を通すたびに、**採用した Before／After をログ節へ追記する**（対象ページ・カテゴリ・修正理由）
2. **同じカテゴリが2回以上出たら**「現在の文体フィンガープリント」への昇格を提案する
3. suggest edit は廃止しない。**残った差分の採取場所**として残し、そこで出た分をログへ入れる

成功条件は「suggest edit の指摘が回を重ねるごとに減ること」。ゼロにすることではない。

## やらないこと

- ルールをスキルファイルへ複製しない
- 自動適用しない
- 📝背景callout・🧑‍⚕️署名calloutを校閲しない（本人の文）
- 文体ゲートを層2.5と別の工程点に増やさない

## 再検討ライン

この工程で3本仕上げた時点で、suggest edit がまだ拾う件数を数える。減っていなければ、
機械の候補出しではなく「書く前に効かせる」側（執筆時の規則）へ比重を移す。
