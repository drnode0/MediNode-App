# 未解決の問いが浮かぶ画面（/cq）設計

作成日: 2026-08-08

## 何を作るか

自分の未解決CQ（Medical DB の「知識レベル = ❓ CQ」）だけが穏やかに漂う全画面。
眺めているうちに「このCQを解決しに行こう」と手が動くことを目的にする。

既存のCQ面（キャプチャ・みんなの臨床疑問の板・解決済み一覧）はどれも一覧か設定の
下にあり、「自分の未解決を眺める場」は無い。この画面はその欠けている一面を足す。

## 浮かぶもの

- 対象は自分の Medical DB の `knowledgeLevel` が `❓ CQ` の行だけ。
  旧値 `❓ クリニカルクエスチョン` も未解決として拾う（未移行データが存在ごと
  消えるのを防ぐ）。
- 💡ナレッジに育った時点で消える。解決の定義を新しく作らず、既存の知識レベルを
  そのまま「未解決／解決」の境界に使う。
- 同時に浮かぶのは最大12件。新しい答えのあるものを優先し、次に新しい順。浮かびきらない分は
  画面下に折りたたんだ通常のリストで置く（浮かべない）。
  全件を浮かべると未解決の山になり、「うるさくしない」原則と逆を向く。

## 新しい答えの数え方

CQを登録した日より後にサブスク側へ入ったナレッジが、そのCQの文言でヒットするか。
ヒットすれば明るく出し、「新しい答えが N 件」を添える。

- 判定は Algolia のマルチクエリで1往復（12件でも1リクエスト）。
- 新旧の比較は Hit の `createdAt`。`createdAt` を持たないヒットは新着扱いしない
  （日付不明を「新しい」と見なすとどのCQにも新しい答えが付いてしまい意味を失う）。
- 明るくなるのはプレミアムのみ。無料は全件が同じ薄さで静かに漂う。
  画面は道具として全員に、新しい答えの提示は中身の価値として有料に置く。

## 触ったとき

泡が止まり、パネルが四つの一手を出す。

1. この文言で探す（自分＋部署＋サブスクを横断）— 新しい答えがある時の既定
2. 作者に投げる（受付DBへ。既存の投稿・通知の配線に乗る）
3. Notionで開く（自分で書く）
4. 解決した — 知識レベルを 💡 ナレッジ に変え、泡が消える

4 が「解決しに行った」の回収。これが無いと未解決が永久に浮かび続ける。
確認ダイアログは出さず、押したら消して数秒だけ「元に戻す」を残す。

パネルには「いつ残した問いか」も出す（例: 2026-01-08 に残した・7か月前）。
経過は月・年で丸める。泡には出さない——全部の泡に日付を並べると、溜めた日数を
毎回見せる催促になる。

## 投げた問いのその後

作者に投げたあと、泡が投げる前とまったく同じ見た目で漂い続けると、送ったのか
どうかすら分からない。既存の配線（受付DB → 板 → 私も気になる → 解決通知）は
通っているのに `/cq` からは一切見えない。ここを埋める。

- 送った → 「作者に届いています」
- 板に載って票がついた → 「3人が同じことを気にしています」
- 作者が答えた → 「答えが出ました」

パネルでは、一度投げた問いから「作者に投げる」を外して状態表示に差し替える
（同じ疑問を二重に送らせない）。色は青緑にして、新しい答えの琥珀と分ける。
別の出来事だから。

状態の出どころは2つを重ねる。

- サーバー（`/api/cq/mine`）… 受付DBの「通知先ユーザーID」で自分の投稿を引く。
  端末を変えても残る。突き合わせは疑問文の一致（`/cq` から投げた文はCQの題そのもの）。
- 端末ローカル（`medinode_cq_sent_v1`）… 通知に同意していない投稿と、
  送った直後のまだ引き直す前。モーダルで題を書き換えた分もここが拾う。

通知に同意していない投稿はサーバー側に自分との紐付けが無く、`/api/cq/mine` には
出ない。同意の線引きを機能のために広げない。

「答えが出た」は受付DBの対応状態から取る。解決後のナレッジは題が書き直されるため、
ナレッジ側との題の一致では追えない。対応状態は「解決」を含む値だけを答えが出たものと
みなす（取り下げを「答えが出た」と言う方が、何も言わないより悪い）。

## みんなが待っている問い（第2の空）

同じ画面の下に、まだ答えの出ていない他人の問いを浮かべる。出どころは2つ。

- 作者のCQ … プレミアム配信DBの「知識レベル = ❓ CQ」。作者が普段どんなことを
  疑問に思っているかがそのまま出る。プレミアムのインデックスから引く。
- 読者投稿 … 受付DBのうち作者が板に出した分（`/api/cq/board`）。従来の板と同じ中身。

どちらにも「気になる」を押せる（プレミアムのみ。既存の `/api/cq/vote` をそのまま使う
——`cq_votes.cq_id` はただの text なので、サブスクのobjectIDも受付DBのページIDも入る）。
票が多い問いほど大きく、はっきり浮かぶ。

**自分の未解決CQとは空を分ける。** 同じ空に混ぜると自分ごとが薄まる。
自分の空が0件でも第2の空は出す（他人の問いは自分の在庫と関係ない）。

押す場所を2つに割らないため、設定の「みんなの臨床疑問 → 受付中」タブは板の本体を
やめてこの画面への導線にする。板のコンポーネント（OpenCqBoard）は削除。

第2の空は設定の「表示のカスタマイズ」で消せる（`hideCommunityCqs`）。
自分の空は消せない——画面の本体なので。

## 入口

- 独立ルート `/cq`。ホームのタブは既に6本あり、7本目は足さない。
- CQボタン（右下のFAB）→ 疑問を残すモーダルのヘッダーに「未解決の問い」。
  CQボタンは疑問まわりの唯一の目印なので、そこから辿れないと設定の奥に埋もれる。
- CQをキャプチャした直後の完了表示に「浮かべておく」導線を置く。
- ヘッダーには、新しい答えのあるCQが1件以上ある時だけ小さな印を出す。
  0件のときは何も出さない（常設のバッジは急かしになる）。

## 構成

| --- | --- |
| `src/lib/floating-cq.ts` | 純ロジック。未解決の抽出・選抜・新しい答えの判定・配置座標・日付表示 |
| `src/lib/unresolved-cqs.ts` | 未解決CQの取得（パワー／シンプル両モード） |
| `src/lib/cq-dispatch.ts` | 投げた問いの端末記録と、状態の突き合わせ |
| `src/lib/cq-mine.ts` | 受付DBの行 → 自分の投稿（純ロジック） |
| `src/lib/pending-query.ts` | 検索タブへキーワードを1回だけ渡す受け渡し口 |
| `src/components/FloatingCqs.tsx` | 浮遊レイアウトとアニメーション |
| `src/components/CqActionSheet.tsx` | 触ったときのパネル |
| `src/lib/community-cqs.ts` | 作者CQ＋読者投稿の合流と並べ替え（純ロジック） |
| `src/components/CommunityCqs.tsx` | 第2の空。票のトグル |
| `src/components/UnresolvedCqLink.tsx` | ヘッダーの静かな入口 |
| `src/app/cq/page.tsx` | 組み立てだけの薄いルート |
| `src/app/dev/floating-cq/page.tsx` | 固定データのdevハーネス（development限定） |
| `src/app/api/notion/resolve-cq/route.ts` | 知識レベルを 💡 に更新 |
| `src/app/api/cq/mine/route.ts` | 自分が投げた疑問とその進み具合 |
| `src/app/api/cq/votes/route.ts` | 「気になる」票のまとめ読み |

- 配置座標は `objectID` のハッシュを種にした決定的な値にする。乱数だと再レンダーの
  たびに泡が飛ぶ。純関数なので vitest で固定できる。
- 取得は両モードで形を揃える。パワーモードは個人 Algolia index を `query=''` と
  知識レベルで絞り、シンプルモードは既存の `/api/notion/search` の `mode:'browse'`
  を使う。
- 新しい答えの判定はクライアント側で完結する。サブスク検索は既に検索専用キーでクライアント
  から叩いており、新しいAPIルートは要らない。
- `resolve-cq` は `create-cq` と同じ作法（DBスキーマから列名を解決、レート制限、
  `requireSessionIfLoginRequired`）。

## 作者アカウントの扱い

作者（`COMP_ADMIN_EMAILS`）がアプリ内から残す疑問は、**個人のMy Medical DBへは保存せず
受付DBだけに入れる**。作者の疑問はサブスクの制作キューそのもので、普段使いの個人知識と
同じ箱に入れると混ざる。判定は `/api/cq/submit` の GET が返す `owner`。

作者の投稿は受付DBの「ボード公開」を既定でONにする。1件ずつNotionでチェックを
入れさせない——出したくない分だけNotion側で外す。結果、作者の疑問はそのまま
「みんなが待っている問い」に並び、会員が「気になる」を押せる。

## 解決した泡が戻る問題

パワーモードの泡の一覧は Algolia から引く。「解決した」は Notion を書き換えるので、
再同期するまで Algolia は ❓CQ のままで、リロードすると片づけた泡が戻ってくる。
押した objectID を端末に控えて一覧から落とす（`medinode_locally_resolved_v1`・60日で失効）。
「元に戻す」を押したら控えからも外す。

## 静けさ

- `prefers-reduced-motion: reduce` でアニメーションを止める。
- `document.hidden` の間は止める（裏で回り続けない）。
- 空状態は「いま浮かんでいる問いはありません」＋キャプチャ導線。

## やらないこと

- 他人のCQを自分の空に混ぜない。自分ごとが薄まる（空を分けることで両立させた）。
- 古さで沈める表現は採らない。溜めた負い目の可視化になる。
- 常設のバッジ・件数表示は置かない。
