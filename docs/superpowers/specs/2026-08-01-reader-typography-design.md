# リーダー組版チューニング（通読性改善）設計

日付: 2026-08-01
背景: アプリ内リーダー（プレミアムナレッジ）が「行間が狭い・詰まって読みにくい」というオーナー体感（スマホ/PC両方）。読みにくさの内訳は「本文の行間・文字の詰まり」「箇条書きの密度」「全体の圧迫感」。

## 方針

要素を足さず、既存の組版（クラス・CSS）だけを調整して通読の質を上げる（案A）。
文字サイズ設定UI（案B）・リーダーモード再設計（案C)は今回スコープ外。効果不足なら案Bを積み増す。

## 変更内容

### 1. 文字の詰まり解消 — `src/app/globals.css`
- `font-feature-settings: 'palt'` を `.reader-prose` 全体から外し、見出し（h1/h2/h3）限定に移す。
  地の文のかな・句読点を自然な字幅に戻す（詰まり体感の主因）。
- `.reader-prose` に `letter-spacing: 0.02em` を追加（日本語通読の微字間）。
- `font-variant-numeric: tabular-nums` は維持（数値の読み比べに有効）。

### 2. 箇条書きを段落と同格に — `src/components/reader/ReaderBody.tsx`
- 項目間: `space-y-1.5` → `space-y-2.5`
- 行間: `leading-[1.85]` → `leading-[1.9]`（段落と統一）

### 3. 息継ぎの余白
- 段落間: `my-3.5` → `my-4`（ReaderBody.tsx）
- コールアウト内側: `px-3.5 py-3` → `px-4 py-3.5`（結論・署名・汎用の3箇所。査読スタンプは現状維持）
- スクロール容器の左右余白: `px-4` → `px-5`（ReaderOverlay.tsx。実質スマホ幅で効く）

### 4. ソフト改行の復元 — ReaderBody.tsx
- 段落・箇条書きに `whitespace-pre-line` を追加し、Notionのshift+Enter改行（rich_text内の`\n`）を
  画面に反映する。現状はHTMLの空白圧縮で潰れて1行に連結される。

## 変えないもの

- 最大行長 `max-w-2xl`（デスクトップ約39字/行 — 適正範囲）
- 確信度マーク・太字マーカー（今回の読みにくさに挙がっていない）
- 表セルの組版（`leading-relaxed`）・査読スタンプ

## 検証

- vitest 既存テストが通ること
- devサーバーで実ナレッジを開き、モバイル幅/デスクトップ幅の前後スクリーンショット比較
