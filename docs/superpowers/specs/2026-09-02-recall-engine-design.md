## 背景・課題

MediNode の検証済みコーパスは、読んだあとに手元に残る仕組みを持っていない。
記事は読了で終わり、既存の「今日の1問」は全員に同じ1問を朝に送る方式で、
本人が読んだ内容と結びついていない。クイズタブは赤背景マーカーを付けた箇所だけを
出題するため、母集団が作者の手作業に依存し、伸びない。

本設計は内の輪（読む → 残す → 確かめる → 定着）を1つの画面 Recall に実装する。
検証済みの主張1つを粒として球に置き、明るさで「思い出せる度合い」を見せ、
忘れかけの主張だけが「確かめる」で球から離脱してカードになる。
間隔反復（SRS）を表や赤バッジでなく、球の物理として表現する。

## 用語

- **主張**: 検証済みコーパスの主張1つ。原文1文（または箇条書き1行）と出典を伴う。ページでも節でもない
- **球**: 主張を単位球面上に置いた全体像。ジャンルごとに区画が連続する
- **残す**: 主張を自分の出題母集団に入れる操作（読了チェック＋自分の Notion への落とし＋出題対象入り、の3役統合。Notion 側は別設計）
- **読んだ**: 記事の節を読み終えたとき、その節に属する主張が自動で受ける状態。出題対象にはならない
- **確かめる**: 忘れかけの主張を球から出してカードにする操作
- **定着**: 復習間隔が90日以上に伸びた主張の表示上の呼び名。卒業ではない
- **篩**: 主張から伏せ字カードを作るときの自動判定と、作者の目視承認

本文の禁止語彙リスト（振る・拾う・血肉など）は UI 文言でも守る。

## 決定事項（サマリ）

1. **粒＝主張1つ。カードは1主張1枚。** ページや節は目印としてだけ使う
2. **球に載せるのは ✅ と ⚠️ の主張と Essentials 形式の主張。❓（不明確）は載せない。** 参考文献DBの行は載せない（根拠であって覚える対象ではない）
3. **明るさ＝記憶の残り（連続量）、色＝状態の種類（未着手／読んだ／残した／定着）。** 光は4段
4. **読んだ節の主張も光るが、出題は「残した」主張だけ**
5. **未着手の主張も球に出す**（棚の全体が見えることが価値。初日を真っ暗にしない）
6. **確かめる＝結合の緩い主張が最大5つ離脱してカードになる。** 定着した主張も期限が来れば離脱する（特別扱いしない）
7. **伏せ字は原文の数値だけを隠す。AI創作はしない。** 数値を持たない主張は全文を伏せる想起カードにする。語の伏せ字は既定にしない
8. **AIで整形した文言を使う場合は管理画面で一覧承認してから有効化する。** 未承認は原文のまま
9. **SRSの段は 1/3/7/14/30/60/120/240/365 日で頭打ち。卒業させない。** 表示上の「定着」は間隔90日以上
10. **ジャンル軸は定義済み34席（33＋INBOX）で固定。INBOX は球に出さない。番号の振り直し禁止・追加は末尾のみ。** 席の位置は収容数を固定定数にして計算し、追加で既存の中心が動かないようにする
11. **主張のジャンルはページのジャンルを継承し、位置は Notion の並びの1つ目（主ジャンル）で決める**
12. **ユーザーの多様さは席の追加でなくレンズで受ける**（自分の領域を選ぶと、その席が手前に来て他が沈む）。v2 の個人・部署の主張は既存の名寄せで34席へ寄せ、合わなければ固定の「その他」席に置く
13. **今日の1問と朝の通知は廃止する**（置換ではない。撤去範囲は後述）
14. **学習記録は Supabase に置く**（端末をまたぐ。既存クイズの localStorage 方式は踏襲しない）
15. **配置と状態計算を描画から分離する。** 描画は Canvas 2D で始め、主張が2,500を超えたら描画層だけ WebGL に差し替える
16. **画面名は Recall。用語は 主張・残す・確かめる・定着**
17. **Recall はオーナー専用で始める。** 既存の `feature-access.ts` に機能 `recall` を足し、専用の許可メール `RECALL_EMAILS`（フォールバック無し。`personal_reader` と同型）にオーナーのメールだけを置く。全員開放の `RECALL_GA` は drnode.com で MediNode を出す判断のときまで置かない。判定はサーバーが正で、利用者側から開ける経路を作らない。閉じている利用者には画面・タブ・設定項目・API のいずれにも Recall の存在を見せない
18. **確認点4件（❓の除外・閾値と枚数の調整可・オーナー専用で開始・見分けの3点）はオーナーが承認済み（2026-09-02）。** 以後は実装の過程で直す

## 主張の定義と取り出し

### 何が主張になるか

対象はサブスク医学DB（公開済みページ）の本文だけ。

- **確信度マーク形式**: 段落または箇条書き1行のうち、✅ か ⚠️ を含む行。行から先頭のマークを外した本文を主張の文とし、行末または直後の出典表記を出典とする。判定は既存の `src/lib/reader-confidence.ts` の `blockConfidence` を使う（U+FE0F の有無に依存しない）
- **Essentials 形式**: 📚Essentials の本文で、節の主張として書かれた行（出典テキストを伴う箇条書き）。取り出し方は `src/lib/subscription-sections.ts` の節分割（`splitIntoSections`）を土台にし、主張行の判定は実装計画で確定する（現物700粒の抽出スクリプトが基準）
- **除外**: ❓の行、⚡結論ボックスの要約行、🧑‍⚕️署名ブロック、見出し、参考文献DBの全行、制作メモ

主張は「ページ・節見出し・本文・出典・確信度・ジャンル（複数）」を持つ。

### 同一性（ID）

主張IDは `ページID ＋ 正規化した本文` のハッシュ。本文が改訂されると別IDになる。
旧IDの主張は `active=false` にし、ユーザーの記録は残す（改訂で鮮度に旗を立てる仕組みは
本設計の範囲外だが、この保持がその前提になる）。並び順・節の移動では ID は変わらない。

### 同期

既存のサブスク同期（`src/app/api/subscription/sync/_core.ts`）の中で、ページ本文から主張を取り出し
`recall_claims` に upsert する。Algolia には載せない（球は Supabase から直接読む）。
同期のたびに、今回見つからなかった主張を `active=false` にする。

## 球の構成

### ジャンル軸

- 席は Notion「ジャンル」プロパティの multi_select 定義に従う。現時点で 01.総論〜33.精神科＋INBOX の34席
- 席の中心はフィボナッチ球面点 `fibPt(番号-1, CAPACITY)` で決める。**CAPACITY は固定定数 64**。
  モックは分母をジャンル数にしているため席を足すと全中心がずれる。これを直す
- 「その他」席は `fibPt(63, 64)` に固定。v2 で名寄せできない個人・部署ジャンルの受け皿。v1 では使わない
- 主張の主ジャンルは、ページの「ジャンル」の Notion 上の並びの1つ目。複数ジャンルの残りは検索・レンズ用の属性として保持する
- 番号の振り直しは `genreHueIndex` の色も同時にずらすため禁止。追加は末尾のみ
- 空席15は穴にならない。次項の容量つき割り当てで、使用中の席の区画が広がる

### 配置（純関数・決定的）

1. 主張数 N の格子点をフィボナッチ球面で作る（密度一様）
2. 使用中の各席の中心へ、席ごとの主張数を容量として、距離の近い順に格子点を割り当てる（容量制約つき最近傍）
3. 席の中では、ページごとに連続した格子点を与える（同じ記事の主張が隣り合う）
4. 主張が増えたとき、個々の位置はわずかに動くが「呼吸は左上」といった近傍関係は保たれる

入力（主張ID・主ジャンル・ページID の列）が同じなら出力は同じ。結果はクライアントでメモ化する。

### 4段の光と色

| 状態 | 条件 | 見え方 |
|---|---|---|
| 未着手 | 読んでも残してもいない | 小さく暗い（存在は見える） |
| 読んだ | 節の読了を記録した。出題しない | 中くらい・彩度の低い灰青 |
| 残した | 自分で残した。出題対象 | 明るい水色。明るさは記憶の残りに比例（後述） |
| 定着 | 残した主張で復習間隔が90日以上 | 最も明るく、淡い後光 |

「読んだ」と「残した」の見分けが弱いのは未解決事項。実装では大きさ（読んだ 7.2 ／ 残した 9）と
色相の両方で差を付け、さらに「残したものだけ」を見るレンズを用意して、実機で確かめる。

### 記憶の残りと結合

主張ごとに `interval_days`（現在の間隔）と `last_reviewed_at` を持つ。

- 残り `r = 1 − 経過日数 / interval_days`（下限 0、上限 1）
- 明るさ `= 0.55 + 0.45 × r`
- 離脱候補は `r < 0.28`。小さい順に最大5つ

期限が来ていない主張は結合が強く離脱しない。「定着」も同じ式に従うので、間隔が長いだけで
期限が来れば離脱する。閾値 0.28 はモックの値で、実測後に調整してよい（定数1か所に置く）。

### 見る操作

- ドラッグで回す。指を離すと慣性で減速し、止まらずにごく遅く回り続ける（reduced-motion では静止）
- ホイールとピンチで 1.0〜3.4 倍に寄れる。1.25倍からジャンル名、2.0倍からページ名、1.8倍から画面上部に「いま見ている区画」を出す
- 主張をタップすると、ジャンル・節・本文冒頭の吹き出しが出る。もう一度タップで閲覧カード（原文＋出典＋「残す」）
- 上部に主張数と「残した／読んだ／未着手」の内訳を常時表示する

## 確かめるの物理

1. 「確かめる」を押すと球が短く揺れ、離脱候補（最大5）が順に手前へ飛び出し、画面下に浅い弧を描いて並ぶ。球は奥へ退き、明るさ42%に落ちる
2. 下の山をタップするとカードが光の点から立ち上がる（モックの「立ち上がる」を採用。「迫り上がる」は不採用）
3. 「覚えた」または「まだ」で答えると、穴の答えが現れ、0.9秒後にカードが閉じて主張が光として元の位置へ帰る
4. 5枚すべて答えるか「戻す」で、球が手前に戻る
5. 候補が0のときは「いま確かめる主張はありません。次は○日後に○件」を出す。「読んだ」だけの主張は候補にしない

離脱アニメーションは 900ms、球の退きと明るさの変化は同時。reduced-motion では位置の移動を即時にし、揺れを省く。

## カードの作り方

### 表（問い）

- **伏せ字カード**（数値を持つ主張）: 原文のまま、数値部分を下線の空欄にする。穴は同種の数値が同一文に並ぶときだけ複数、上限3。全穴は文が読めなくなるので禁止
- **想起カード**（数値を持たない主張）: ページ名と節見出しを出し、本文は伏せる。「この節の主張を思い出す」の1行を添える
- どちらもページ名・節見出し・確信度マークを表に出す。選択肢は出さない

### 裏（答え）

原文の全文＋出典＋確信度マーク。AIによる解説は付けない。

### 穴の検出（篩の自動段）

- 対象: 単位を伴う数値（mmHg・mL/kg・%・mg・時間・日・回など）と比較値
- 除外: 研究記述子（合意率・RR・OR・HR・95%CI・p値・n=・statement 番号・Level・年号・出典内の数値）
- 同一文で同種の単位が並ぶときは1つの穴にまとめず、上限3で複数穴にする
- 検出結果は主張ごとに `holes`（文字位置の範囲の配列）として保存する

### 篩の承認（管理画面）

- 管理画面に「Recall カード」一覧を置く。伏せ字候補（現時点380）をページ順に並べ、各行に表の見え方・裏・出典を出す
- 操作は3つ: 出す／出さない／穴を直す（範囲の追加・削除）。既定は「未承認」
- **未承認の主張は想起カードとして出る**（伏せ字にしないだけで、球からも出題からも外れない）。初日から球全体が動く
- 承認状態は `recall_claims.cloze_status` に持つ。ID が変わる改訂が入ると未承認に戻る
- AI整形文言を使う場合も同じ一覧で承認する（v1 では使わない。欄だけ予約）

Recall はオーナー専用で始めるため、撤去は Recall の公開に結びつけない。今日の1問は「置換」でなく
「廃止」と決めているので、Recall がオーナーの実測で動くと確認できた時点で、独立した1ステップとして消す。
消すまでの間、一般の利用者には今日の1問が従来どおり見える。

## 描画の天井と分離方針

### 層の分離

| 層 | 役割 | 入力 → 出力 | テスト |
|---|---|---|---|
| 読み込み | `recall_claims` と本人の記録を取得 | Supabase → 主張列＋記録 | API のモック |
| 配置 | 主張列＋席定義 → 単位ベクトル | 純関数・決定的 | 実データ700粒で同一入力＝同一出力、席追加で既存中心が不動 |
| 状態 | 記録＋現在時刻 → 状態・明るさ・離脱候補 | 純関数 | 日付を進めて段と候補を検証 |
| 描画 | 位置・状態・カメラ → 画面 | Canvas 2D（v1） | 実機で ms 計測 |
| 操作 | ポインタ・ホイール → カメラ・選択 | | |

描画層は `render(frame)` の1つの入口だけを持ち、配置・状態は描画を知らない。

### 天井

Mac 実測で 5,000 主張が 10.4ms。実機はこれより遅いので、実用の天井は 2,000〜3,000 と見る。
1ページ約26主張なので、公開ページが100枚前後で当たる。**active な主張が 2,500 を超えたら**、
描画層だけを WebGL（インスタンス描画）に差し替える。配置・状態の層は変えない。

### 描画の約束

- devicePixelRatio は 2 で頭打ち
- タブが非表示のときは requestAnimationFrame を止める
- reduced-motion では自転・揺らぎ・離脱の弧を省き、位置変更は即時
- スプライトは状態ごとに事前描画し、フレーム内で drawImage だけを行う

## 画面と導線

- **Recall 画面**: 球＋上部の内訳＋下部の「確かめる」。ホームのタブ構成のどこに置くかは実装計画で決める（今日の1問が占めていた位置を候補にする）。`hasFeature('recall')` が偽の利用者にはタブも導線も描かない
- **API**: Recall 用の全ルート（主張の取得・記録の読み書き・管理画面の承認）は、サーバーで `hasFeature('recall')` を確認し、偽なら 404 を返す
- **読む画面からの「残す」**: 記事の主張行に「残す」を置く。押すと `recall_progress` に入る。節の読了は `recall_section_reads` に入る。Notion への落としは別設計（拾う＋Notion DB）で決め、ここでは `recall_progress` への書き込みを接点とする
- **外の輪からの接点**: 段0で引いた主張の「拾う」は同じ `recall_progress` へ書く
- **管理画面**: 「Recall カード」一覧（篩の承認）を追加する

## 検証の考え方

- 配置・状態・穴検出は純関数にし、テストは自作の文字列でなく **実データ（`.preview/grains.json` 相当の700粒）** を通す
- 穴検出は、20問の目視サンプル（出せる13・微妙4・出せない3）を回帰テストとして固定する
- SRS は日付を注入して 1→3→7…→365 の段と「まだ」での巻き戻しを検証する
- 描画は実機 iPhone で 700 と 2,500 の ms を測り、Notion の作業ログに記録する
- 「読んだ」と「残した」の見分け、動きの気持ちよさはブラウザペインを表示状態にして確認する（非表示だとアニメーションが進まない）

## 本設計で決めないこと

- Notion 側の受け皿（拾う＋Notion DB 自動作成・段0接続）。別セッションで設計する
- 個人・部署ナレッジの主張を球に出すか（v2。出すなら別色と「その他」席）
- 週1レポートの中身
- 費用方式（早期アクセスでの実測後）
- クイズタブと Recall の統合
- 語の伏せ字、AI整形文言の実運用
- 改訂された主張への旗の立て方（記録の保持だけ本設計で確保する）
