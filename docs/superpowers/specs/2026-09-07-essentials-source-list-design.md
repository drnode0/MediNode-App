# Essentials タブに出典の一覧を出す／段階の色を8色にする 設計

日付: 2026-09-07　状態: オーナー承認済み
実装: 同セッション（`superpowers:writing-plans` → 実装）

## 目的

`/admin` の Essentials タブが「どんな文献を集めたのか」に答えるようにする。
今の画面は段階の内訳と領域ごとの円グラフが大半を占めていて、台帳に何が入っているか（誌・年・役割・状態）は
主題の行を1つずつ開かないと見えない。あわせて、段階の色が似通っていて見分けられない問題を直す。

背景（2026-09-07 の実測）: 台帳は63件。状態は全文41・未取得20・抄録2。役割はガイドライン24・主要RCT18・
コホート/観察研究9ほか。年は1987〜2025（中央2018）。61/63 が主題に紐づく。「主張」列はほぼ空（1件）。

## 変更1: 出典の一覧（`src/app/admin/EssentialsCard.tsx`）

**APIは変えない。** `/api/admin/essentials` はすでに台帳の全行（`EssentialsSource[]`）を返している。画面だけで足す。

### 置き場所

「主題の一覧」の下、「次に取る出典」の上。

### 中身

- 1行1文献。列は **文献名（Notionへのリンク）／役割／誌／年／状態／紐づく主題**。
  紐づく主題は数と、1件なら主題名、2件以上なら「主題名 ほかN件」。
- 63件を一度に出す（折りたたまない）。件数は見出しの右に「N / 63 件」で出す。
- 絞り込みは**状態・役割・誰が取るか・キーワード**（文献名と誌の部分一致）。既存の「主題の一覧」と同じ流儀の
  `select` とテキスト入力を1行に並べる。
- 並び替えは**年の新しい順（既定）／年の古い順／役割（背骨が先）／誌**。列見出しを押して切り替える。
- 主題に紐づかない行（実測2件）も落とさずに出す。台帳に入れたが主題を付け忘れた行を見つけるため。

### 誌の内訳

表の上に、**誌ごとの件数を多い順に上位8つ**（それ以下は「その他 N」）を小さく出す。
実測で同じ雑誌が「NEJM」10件と「N Engl J Med」8件に割れており、一覧を眺めても気づけない。

**自動の名寄せはしない。** 略記と正式名を機械で束ねると別の雑誌を混ぜる。件数を並べて出すところまでを画面の仕事にし、
直すかどうかは Notion 側で人が決める。

## 変更2: 段階の色を8色にする（`src/app/admin/EssentialsCard.tsx`）

8段を1色の濃淡（青のみ、のちに灰・青・緑の3群）で出していたが、実データでは135主題中128件が「2 収集済」に
集まるため、どのリングもほぼ1色になり、進んだ段階の小さな片がその中に埋もれる。**段階ごとに別の色相**にする。

| 段階 | ライト | ダーク |
|---|---|---|
| 0 未収集 | `#cbd5e1` | `#4b5563` |
| 1 収集中 | `#7d7d7a` | `#94a3b8` |
| 2 収集済 | `#2a78d6` | `#3987e5` |
| 3 骨子済 | `#eb6834` | `#d95926` |
| 4 本文済 | `#1baf7a` | `#199e70` |
| 5 層3済 | `#eda100` | `#c98500` |
| 6 サブスク移行済 | `#e87ba4` | `#d55181` |
| 7 スプレッド公開 | `#008300` | `#008300` |

- 未収集は薄く沈め、完了（スプレッド公開）を緑にする。
- 配色検証（`dataviz` スキルの validator）を通した値。隣り合う段の見分けは
  **ライト normal ΔE 16.7 以上・CVD 9.1 以上／ダーク normal 15.4 以上・CVD 8.4 以上**。
- 薄い色は下地との対比が 3:1 に届かないので、**色だけで意味を運ばない**。凡例・帯・表には段階名を必ず添える
  （現状すでにそうなっている。この性質を壊さない）。
- **色の順序では進み具合を読めなくなる**（オーナー了承済み）。順序は番号と並び順で読む。

## やらないこと

- 領域ごとの円グラフの変更（そのまま残す・2026-09-07 オーナー判断）
- 誌名の名寄せ、台帳の書き戻し（Notion 側で行う）
- APIの変更、新しい取得経路

## 検証

- 既存のテストが通る（このタブのAPIテストは変わらない）
- `essentials-admin.ts` に足す純関数（誌の内訳・出典の絞り込みと並び替え）にテストを書く
- 本番の実データ63件で、絞り込み・並び替えの結果が台帳と一致することを確かめる
- 画面はオーナーが `/admin` で目視（管理者セッションが要るため）
