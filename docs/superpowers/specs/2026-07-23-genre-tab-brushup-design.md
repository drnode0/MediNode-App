# ジャンルタブ ブラッシュアップ 設計

日付: 2026-07-23
対象: MediNode アプリ ジャンルタブ（`activeTab === 'browse'` → `GenreBrowse`）
ブランチ: `feat/genre-tab-brushup`

## 背景 / 課題

ユーザー（tatsuki）からのUXフィードバック。ジャンルタブが「見づらい」。スクショで確認できた実因は3つ：

1. **同名ジャンルの重複**: 「呼吸」「感染症」が2枚ずつ、「呼吸器」まで並ぶ。
   原因は、個人DBの `02.呼吸`（表示時に番号を落として「呼吸」）と、部署DBの番号なし `呼吸` を
   **別ジャンルとして別チップ**にしているため。`GenreList` の `sortedGenres` が
   `Object.keys` を owner 横断で union するだけ（`GenreBrowse.tsx:289-293`）で、
   表示名が同一でもキーが違えば別チップになる。`displayGenreName`（`GenreBrowse.tsx:139-141`）が
   番号を落とすので、見た目だけ同名の2枚が生まれる。
2. **色が並び順で巡回して雑然**: `genreChipTone`（`GenreBrowse.tsx:117-137`）が番号順に
   ペール5色を巡回。淡色ベタ塗り背景（`bg-amber-50` 等）で全体がうるさい。
3. **フィルタチップが全部同じ緑**: 選択中チップが一律 `bg-brand-600`（`GenreBrowse.tsx:174`）。
   部署が複数あってもどれも同じ緑で区別できない。

補足で挙がった「ジャンル検索タブ」は、上部ナビ（検索/新着/ジャンル/文献/クイズ/マニュアル＝6つ）を
増やさず、ジャンル一覧上の**インライン絞り込み**で同等の効果を出す方針に変更。

## スコープ（確定）

含める:
- **A. 同名ジャンルの統合**（文字一致のみ）
- **B. チップの見た目 = 中立寄り＋左色帯**
- **C. 部署カラー体系**（ドット＋フィルタチップを部署ごとに色分け）
- **D. インライン絞り込み**（タブは増やさない）

含めない（明示的に却下）:
- 同義語マージ辞書（`呼吸器内科 → 呼吸` の丸め）。ユーザーの粒度自由を壊すため不採用。
- 推奨ジャンル雛形（テンプレ）。今回はスコープ外、必要になれば別セッション。

対象コンポーネント: `src/components/GenreBrowse.tsx` に閉じる。
- チップ着色（C）は `GenreBrowse` 内の `GenreOwnerFilterTabs`（ローカル）だけを触る。
  アプリ全体で使う `src/components/OwnerFilterTabs.tsx` は**変更しない**
  （「ジャンルの時だけ色を付ける」という要望に一致）。
- `genreChipTone` は search タブのジャンル絞り込みチップ（`page.tsx:2031` 等）でも使われるため、
  **戻り値のシグネチャは変えない**。左色帯化はGenreBrowse側のマークアップ変更で行い、
  他コンシューマの見た目は変えない。

## 設計詳細

### A. 同名ジャンルの統合（文字一致のみ）

正規化キー = `displayGenreName(genre).trim()`（番号プレフィックス除去＋trim）。
同一正規化キーに落ちる複数のファセットキーを**1チップに束ねる**。

- **束ねるのは「表示名が文字として完全一致」した時だけ**。`呼吸器内科` と `呼吸器外科` は
  文字が違うので絶対に統合されない（粒度を分けたい人は守られる）。
- 統合チップが持つ情報:
  - 表示名 = 正規化キー
  - 件数 = 現在の owner ビューにおける、束ねた全variantの合算
  - 左色帯の色 = 束ねたvariantのうち**番号付きのもの**を優先して `genreChipTone` に渡す
    （番号があれば並び順の色が安定）。番号付きが無ければ正規化キーのハッシュ。
  - ドット = 束ねたvariantのいずれかが該当部署/プレミアムにあれば点灯（C参照）
- **選択時のフィルタ（実装の肝）**: 統合チップ選択時は、束ねた**全variantキー**を対象に引く。
  - 個人/プレミアム（Algolia、`SelectedGenreView`）: `genre:"02.呼吸" OR genre:"呼吸"` の OR フィルタを
    variant集合から組み立てる（現状は単一 `genre:"${genre}"` 完全一致 = `GenreBrowse.tsx:471,512-513`）。
  - 部署（Notionメモリ上、`teamGenreHits` = `GenreBrowse.tsx:562-565`）:
    `getHitGenres(h).includes(selectedGenre)` を「hitのジャンルを正規化した集合が
    選択正規化キーを含むか」に変更。
  - 実装方針: `GenreList` が計算した `正規化キー → variantキー[]` のマップを、選択時に使えるよう
    `GenreBrowse` へ持ち上げる（`onGenreSelect` で正規化キーと同時にvariant集合を渡す、
    もしくは選択後に再計算）。

### B. チップの見た目 = 中立寄り＋左色帯

- 地: 白 / 薄グレー（例: `bg-white dark:bg-gray-800/60`、境界 `border-gray-200 dark:border-gray-700`）。
- 左端: 3〜4px の色帯。色は既存5色巡回（`genreChipTone` の色相を帯に転用）。
- 名前・件数: 中立色（`text-gray-800 dark:text-gray-200` / 件数は `opacity-50`）。
- 選択中: 左色帯は残したまま、地を**その帯色の薄いtint**に切替（例: `bg-amber-50 dark:bg-amber-900/25`）。
  ベタ塗り白文字はやめ、中立基調を保つ。
- 実装メモ: 現状 `tone.active`/`tone.idle` は背景クラス一式。左色帯化に伴い、
  `genreChipTone` の戻り値はそのまま（他コンシューマ用）にし、GenreBrowse では
  「色相トークン → 左border色クラス」への写像を別途持つ。色相の対応（緑/琥珀/空/菫/薔薇）は
  既存巡回ロジックを流用。

### C. 部署カラー体系（ドット＋フィルタチップ統一）

部署に**順番で色を割り当てる**。順序 = `[primaryTeam, ...additionalTeams]`
（`GenreOwnerFilterTabs` の `teamChips` 構築順 = `GenreBrowse.tsx:155-160`）。

- **部署カラーパレット**（紫はプレミアム予約なので除外）:
  `[green(emerald), amber, sky, rose, teal, orange]` の順、超えたら巡回。
- 色の割当基準: 部署リスト（`[primaryTeam, ...additionalTeams]` = 設定の追加順）内の**位置（index）**。
  1個目=緑（固定。既存の緑ドット意味論と連続）、2個目=琥珀(黄)、…。パレット内は必ず別色になるので
  distinctness（見分けやすさ）を最優先で担保。
  - **代替案を検討して不採用**:
    - ID固定ハッシュ（teamIdから色）→ 6色に対し2〜3部署でも色衝突しやすく、
      「見分けたい」という目的を直接壊すので不採用。
    - 色を設定に永続保存（追加時に空き色を確保して固定）→ 最も堅牢だが、飾りのドット色のために
      settings migration＋割当ロジックは過剰（YAGNI）。今回は入れない。
  - **位置順の弱点と許容理由**: 途中の部署を**削除**した時だけ以降の色がずれる。ただし部署は通常
    末尾に**追加**するので追加では既存色は動かず、実害は稀な中間削除時に飾り色がずれるだけ。
    ユーザー了承済み。将来ずれが問題化したら永続保存案へ上げる（余白として残す）。
- **ジャンルチップのドット**:
  - その部署にジャンルがあれば、**その部署の色**のドットを表示。
  - 複数部署にあれば**複数ドット**を並べる。
  - プレミアムにもあれば従来どおり**紫ドット**。
  - これには per-department のジャンル集計が必要。現状 `teamFacets` は全部署を1つに合算
    （`GenreBrowse.tsx:552-559`）。これを `Record<teamId, Record<genre, number>>` に拡張する
    （`teamHits` は既に `h.teamId` を持つ）。「全て」ビューの合計件数は従来通り
    personal+team(全部署)+sub で出す。
- **フィルタチップ**（`GenreOwnerFilterTabs`）:
  - 全て = 中立ダーク（例: 選択中 `bg-gray-900 text-white`）。※部署の緑と衝突させない。
  - 個人 = 中立（選択中 中立ダーク）。
  - プレミアム = 紫（選択中 紫塗り、idle 薄紫）。
  - 各部署 = その部署色（選択中 その色塗り、idle その色の薄いtint）。
  - 個々の部署はラベル文字（例: 救急 / ICU）＋色で判別。
- **凡例**（`GenreDotLegend` = `GenreBrowse.tsx:196-215`）:
  - 現在「部署にもあります(緑)」「プレミアムにもあります(紫)」の2行固定。
  - 部署ごとに1行、その部署色で「〇〇にもあります」を列挙するよう拡張。
  - 引数を `showTeam:boolean` から「表示すべき部署の配列（label＋色）」に変更。
  - 表示条件は従来どおり: 「全て」ビューかつ画面内に実際にそのドットがある時だけ。

### D. インライン絞り込み（タブは増やさない）

- ジャンル一覧の上に小さな入力。プレースホルダ「ジャンルを絞り込む」。
- 挙動: 入力に対し、表示名の**部分一致**で `sortedGenres` を絞る。「循環」→ 循環 / 循環器 が残る。
- 絞り込み中は折りたたみ（`GENRE_SHOW_LIMIT = 12` / `GenreBrowse.tsx:89,321-322`）を**解除して全件表示**。
- クリアボタン（×）付き。owner切替時は入力をクリア。
- **表示条件**: ジャンルが多い時だけ入力を出す（`sortedGenres.length > GENRE_SHOW_LIMIT`）。
  少数の時は不要なので出さない（うざくない原則）。

## 影響範囲 / 非対象

- 変更: `src/components/GenreBrowse.tsx` に閉じる想定。
- **非変更**: `src/components/OwnerFilterTabs.tsx`（アプリ全体共用。色は付けない）、
  search タブのジャンル絞り込みチップ（`page.tsx` の `genreChipTone` コンシューマ。
  `genreChipTone` の戻り値を変えないことで見た目維持）。
- データ/Notion側の変更なし。Algoliaインデックス変更なし。migrationなし。

## リスク / 確認事項

1. **統合の選択フィルタ**: variant OR を組めていないと、統合チップを押しても片方しか出ない。
   ここが一番のバグ源。個人・プレミアム・部署の3経路すべてでvariant集合を使うこと。
2. **per-department facet**: `teamFacets` の構造変更が `SelectedGenreView` の部署hit絞り込み
   （`GenreBrowse.tsx:489-491`）と整合しているか。
3. **部署色の安定性**: 追加順（位置）基準。追加では既存色不変、中間削除時のみ色ずれ。
   distinctness優先で位置基準を採用済み（ID固定/永続保存は不採用理由をC節に記載）。仕様として許容。
4. **ダークモード**: 左色帯・部署tint・中立地の全パターンでdark時のコントラストを確認。
5. **凡例のドット実在チェック**: per-department化後も「画面内に実際にドットがある部署だけ」
   凡例に出す条件を維持（無関係な部署が凡例に並ばないように）。
